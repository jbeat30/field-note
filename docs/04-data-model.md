# 데이터 모델 (0단계 계정·동의)

> 기술 기획서 §17 "데이터 모델 기획"을 단계별로 쌓는 문서. 이번 버전은 0단계(P0-1) 범위만 다룬다.
> 기준: 서비스 기획서 §5.1 회사 격리, §5.6 수집 항목, §5.7 동의, §6.1 계정 구조 / 기술 기획서 §8 회사 격리 구현

## 1. 테이블

| 테이블                | 용도                                                               | 범위      | 핵심 규칙                                                                                                                                                                                                                                                                                                                         |
| --------------------- | ------------------------------------------------------------------ | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `companies`           | 회사                                                               | 회사 자체 | `status`(ACTIVE·SUSPENDED·CLOSING·CLOSED). 정지·해지 요청 중에는 로그인 차단, 삭제가 끝나면 CLOSED(이름은 익명화)                                                                                                                                                                                                                 |
| `users`               | 회사 관리자 계정                                                   | 회사 범위 | **회사당 하나**(`company_id` 유일). 이메일은 인증 전 비어 있고 서비스 전체에서 유일(소문자)                                                                                                                                                                                                                                       |
| `user_credentials`    | 로그인 아이디·비밀번호 해시                                        | 회사 범위 | 아이디는 서비스 전체에서 유일(소문자). **전용 계정만 접근**, 앱 계정은 권한 없음                                                                                                                                                                                                                                                  |
| `sessions`            | 로그인 세션                                                        | 회사 범위 | 토큰은 해시만 저장. `(company_id, user_id)`가 `users`를 참조해 다른 회사 계정과 연결 불가 기기 목록용으로 공개 식별자(`public_id`), 기기 이름(`device_label`, 예: Chrome · macOS), 마지막 사용 시각(`last_active_at`)을 가짐. IP·접속 정보 원문은 저장하지 않음                                                                   |
| `invitations`         | 운영자가 발급하는 1회용 초대 링크                                  | 회사 범위 | 토큰은 해시만 저장. `used_at`이 있으면 폐기, 만료·정지된 회사·가입 완료 계정은 무효. 운영자·전용 계정만 접근                                                                                                                                                                                                                      |
| `operator_actions`    | 운영자 작업 기록 (회사 생성·초대 발급)                             | 회사 범위 | **추가만 가능**, 개인정보 없이 회사 식별값·작업자만 기록. 운영자 계정만 접근                                                                                                                                                                                                                                                      |
| `email_verifications` | 이메일 인증 코드 상태 (사용자당 한 행)                             | 회사 범위 | 코드는 HMAC 해시만 저장, 유효 10분·틀린 입력 5번·재발송 30초 간격·시간당 5번. 전용 계정만 접근, 삭제 권한 없음                                                                                                                                                                                                                    |
| `password_resets`     | 비밀번호 재설정 링크 상태 (사용자당 한 행)                         | 회사 범위 | 토큰은 SHA-256 해시만 저장, 유효 30분·한 번 사용하면 해시를 비워 폐기, 요청 1분 간격·시간당 5번. 전용 계정만 접근, 삭제 권한 없음                                                                                                                                                                                                 |
| `company_settings`    | 회사 설정 (회사당 한 행, 없으면 기본값)                            | 회사 범위 | 하루 기준시간(분, 60~960)·월 기준일수(1~31)·공수 방식(비율·시간), 범위는 DB도 검사. 앱 계정이 자기 회사 행만 조회·생성·수정, 삭제 권한 없음                                                                                                                                                                                       |
| `option_items`        | 선택 목록 항목 (직종·작업 구분·공종·직원 구분)                     | 회사 범위 | `(company_id, kind, name_key)` 유일(공백·대소문자 차이는 같은 이름), 이름 1~30자, 종류마다 100개(API가 검사). **삭제 권한 없음**: 쓰지 않는 항목은 `is_active=false`로 숨김. 처음 조회할 때 프리셋으로 채움. 앱 계정이 자기 회사 행만 조회·생성·수정                                                                              |
| `employees`           | 직원 카드 (이름·직책·직종·구분·상태·입퇴사일·생년월일·연락처·메모) | 회사 범위 | 이름 1~50자(필수), 직종·직원 구분은 같은 회사의 `option_items`를 복합 키로 참조(비어 있으면 검사 안 함). 상태(재직·휴직·퇴사)와 퇴사일은 함께 움직임(DB도 검사: 퇴사 ⇔ 퇴사일 있음), 퇴사일 ≥ 입사일. **삭제 권한 없음**(퇴사는 상태 변경). 주민등록번호·계좌번호·급여 컬럼 없음. 목록 API는 생년월일·연락처·메모를 내보내지 않음 |
| `partners`            | 명부 (고객·협력업체·자재 공급처: 상호·담당자·연락처·메모)          | 회사 범위 | `(company_id, kind, name_key)` 유일(같은 구분 안에서 공백·대소문자 차이는 같은 상호), 상호 1~50자, 구분은 등록 후 변경 불가(API). **삭제 권한 없음**: 쓰지 않는 업체는 `is_active=false`로 숨김. 금액·거래 내역 컬럼 없음. 목록 API는 연락처·메모를 내보내지 않음                                                                 |
| `company_closures`    | 해지 요청 (회사당 한 행)                                           | 회사 범위 | 요청·삭제 예정(`purge_after`, 요청 14일 뒤)·취소 링크 해시(1회용)·취소·삭제 완료 시각. 취소 후 다시 요청하면 행을 새로 채움. 전용 계정이 요청·취소를 처리하고 삭제 계정은 조회와 삭제 완료 시각 기록만. **삭제 후에도 개인정보 없이 남김(파기 증빙)**                                                                             |
| `social_accounts`     | 소셜 로그인 연동 (제공자·제공자 사용자 번호)                       | 회사 범위 | `(provider, provider_user_id)` 유일, 한 계정에 같은 제공자는 하나. 이메일로는 연결하지 않음. 전용 계정만 접근, 삭제는 연동 해제용으로만 허용                                                                                                                                                                                      |
| `legal_documents`     | 약관·처리방침·마케팅 수신 문서의 버전                              | 공용      | `(type, version)` 유일. 본문 해시로 동의 시점의 내용을 증명. 두 계정 모두 **조회만** 가능. 본문은 코드(`packages/shared/src/legal.ts`)에서 관리하고 DB에는 해시만 저장하며, 운영자가 `pnpm operator legal-register`로 등록(같은 버전의 내용 변경은 거부)                                                                          |
| `consents`            | 동의 이력                                                          | 회사 범위 | **추가만 가능**. 철회는 `is_agreed=false` 행을 추가하고 가장 최근 행이 현재 상태                                                                                                                                                                                                                                                  |
| `projects`, `memos`   | 격리 검증용 샘플 (T0-4)                                            | 회사 범위 | 업무 테이블이 생기면 정리                                                                                                                                                                                                                                                                                                         |

## 2. DB 계정별 권한

| 계정                             | 용도                                | 접근                                                                                                                                                         |
| -------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `field_note` (소유)              | 마이그레이션·운영 경로              | 전체. 회사·약관 문서 등록은 운영 경로(운영자 CLI는 아래 운영자 계정)                                                                                         |
| `field_note_app` (앱)            | 로그인 후 업무 쿼리                 | 자기 회사 행만(RLS): `users`·`consents` 조회, `projects`·`memos` 조회·생성·수정. 비밀번호 해시·세션에는 접근 불가                                            |
| `field_note_queue` (작업 큐)     | pg-boss 작업 큐                     | 큐 스키마(`pgboss`)만 소유·사용. **업무 테이블 접근 불가**                                                                                                   |
| `field_note_operator` (운영자)   | 운영자 CLI(`pnpm operator`)         | 회사·계정·초대 발급과 작업 기록만. **업무 테이블·세션·비밀번호·동의 이력 접근 불가**, 작업 기록은 추가만 가능                                                |
| `field_note_purge` (삭제)        | 해지 유예가 끝난 회사의 삭제·익명화 | **해지 중(CLOSING)인 회사의 행만** 보임(RLS). 삭제 대상 테이블은 삭제만, `users`·`companies`는 개인 식별 컬럼만 수정, 동의 이력·운영자 작업 기록은 접근 불가 |
| `field_note_auth` (회사 범위 밖) | 로그인·가입·세션 처리               | 모든 행(회사를 아직 모르는 시점): `users`·`user_credentials`·`sessions` 처리, `companies` 조회, `consents` 추가                                              |

- 어느 계정도 `consents`를 수정·삭제할 수 없고, 앱 계정은 어떤 테이블도 삭제할 수 없다
- 새 테이블은 `company_id`와 RLS 정책이 없으면 스키마 검사 테스트가 실패한다. 회사와 무관한 공용 자료는 `schemaCheck.test.ts`의 `GLOBAL_TABLES`에 명시적으로 등록한다

## 3. 서비스 기획서와의 대응

| 요구사항                                                  | 구현                                                                   |
| --------------------------------------------------------- | ---------------------------------------------------------------------- |
| 한 회사에 계정 하나, 로그인 아이디는 서비스 전체에서 유일 | `users.company_id` 유일, `user_credentials.login_id` 유일              |
| 인증된 이메일이 있어야 계정 사용                          | `users.email`, `email_verified_at` (인증 흐름은 P0-4)                  |
| 동의 일시와 문서 버전 기록, 마케팅은 별도 선택            | `consents.decided_at`, `legal_documents.type=MARKETING`, `is_required` |
| 만 14세 미만 가입 불가 확인                               | `users.age_confirmed_at` (가입 흐름은 P0-3)                            |
| 비밀번호는 복원 불가 형태로 저장                          | `user_credentials.password_hash` (해시 알고리즘 적용은 P0-3)           |
| 소셜 로그인만 쓰는 계정 가능                              | `login_id`·`password_hash`가 비어 있을 수 있음 (연동 테이블은 P0-7)    |
| 주민등록번호·계좌번호 저장하지 않음                       | 해당 컬럼 없음                                                         |
