# 프로젝트 중심 UX 재설계 (프로젝트·작업 내역)

> 작성: 2026-10-13 · 기준: **대표가 프로젝트별로 회사를 관리**하려고 만든 서비스. 일의 기록은 프로젝트 안에서 날짜마다 남긴다

## 1. 서비스가 푸는 문제

- 대표(관리자)는 **프로젝트(공사 건)** 단위로 사람·일·자재·사진·서류·비용을 본다. 현장 직원이 "내 현장"을 따로 갖는 서비스가 아니다
- 현장 사람은 프로젝트별로 관리된다: 어느 프로젝트에 누가 배정됐고, **날짜마다 누가 몇 시간 무슨 일을 했는지**가 핵심 기록이다 (사람마다 일한 시간이 다를 수 있다)
- 그래서 "일지"라는 별도 개념과 별도 메뉴를 없애고, **프로젝트 안의 "작업 내역"(날짜별)** 으로 다룬다

## 2. 이전 설계의 잘못 (되돌아본 점)

| #   | 문제                                                                                    | 고친 방향                                                              |
| --- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| P1  | "일지"가 프로젝트와 따로 있는 최상위 메뉴였다. 쓰려면 프로젝트를 고르는 선택칸부터 시작 | 일지 메뉴 삭제. 프로젝트에 들어가면 **작업 내역**이 첫 화면            |
| P2  | 한 번에 같은 일·같은 시간만 정하는 입력(전원 적용)이 중심이었다                         | **사람마다 일한 시간**을 따로 정하는 것이 기본 (모두 같게는 보조 버튼) |
| P3  | 일지·사진·자재·메모가 서로 다른 곳에 있었다                                             | 하루 작업 화면에 **그날 사진·자재**를 함께 둔다                        |
| P4  | "공수(MD)·작업 구분·투입" 같은 사무 용어                                                | 입력은 **시간**, "무슨 일", "배정 인원"으로                            |
| P5  | 홈이 "오늘 내 현장" 같은 개인 관점이었다 (잘못 이해함)                                  | 홈은 회사 전체 프로젝트 현황·확인할 것·이번 주 인력 (기존 구성)        |

## 3. 새 구조

### 3.1 프로젝트 작업 공간 (`/projects/:id`)

머리: 프로젝트 이름·상태·남은 기간, `오늘 작업 입력` 버튼, 고객·담당자·기간.
메뉴(탭): **작업**(기본) · 현황 · 사진 · 자재 · 메모 · 문서 · 배정 인원 · 일한 양·인건비 · 추가 공사 · 일보 출력 · 마감 요약 · (보수·보증) · 정보 수정

### 3.2 작업 내역 (`/projects/:id`, 첫 화면)

- 날짜별 표(최근 날짜 먼저): 날짜 · 상태(임시 저장/저장됨) · 일한 시간 합계 · 기록한 항목 수 · 표시(늦게 입력·추가 공사 …). 열 머리로 정렬, 쪽 나누기
- 맨 위: `오늘 작업 입력`(이미 있으면 `오늘 작업 고치기`), 다른 날짜를 골라 입력·고치기

### 3.3 하루 작업 (`/projects/:id/work/:date`)

1. 날짜 이동(전날·다음 날·오늘·달력)
2. **일한 사람과 시간**: 배정된 사람이 나와 있고, 사람마다 `체크(출근)` · `무슨 일` · `시간(−30분/+30분, 반일·하루·연장)` · `다른 일도 했어요`(한 사람이 여러 일). 위에 `전원 반일/하루/연장`, `무슨 일 모두 적용`, `어제와 똑같이 채우기`
3. **한 일**: 작업 내용(필수)·작업 구역·날씨·특이사항·추가 공사 표시
4. **이 날 사진**(그날 올린 사진, 올리기는 사진첩), **자재**(그날 반입·사용)
5. 아래 고정 줄: 합계(몇 명·몇 시간) + `임시 저장` `저장`

### 3.4 메뉴·홈

- 아래 메뉴(모바일): 홈 · 프로젝트 · 인력 배치 · 직원 · 더보기(메모함·명부·월 공수표·설정). 왼쪽 메뉴(넓은 화면): "프로젝트 관리"(홈·프로젝트·인력 배치·메모함)와 "관리"(직원·명부·월 공수표·설정)
- 옛 주소 `/work-logs?project=&date=`는 프로젝트의 작업 화면으로 자동 이동

## 4. 구현 메모

- 서버 계약은 그대로다 (`work-logs` API). 화면 이름만 "작업 내역"으로 바꿨고, 화면 문구의 "일지"는 모두 "작업 내역"으로 통일했다
- 입력 단위는 항상 시간이다 (저장은 분). 회사의 "공수 입력 방식(비율·시간)" 설정은 작업 입력에는 쓰이지 않고 집계 표시(월 공수표 등)에만 영향
- 사진은 `workDate` 조건으로 그날 사진만 조회한다 (API가 이미 지원)
- 알림 "오늘 작업 내역이 없음"은 프로젝트의 작업 내역 화면으로, 소진율·지연 알림은 프로젝트 현황으로 연결된다
