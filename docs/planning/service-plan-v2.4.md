# 현장 팀 프로젝트 관리 서비스 기획서 (v2.4)

> 작성일: 2026-10-04
> 문서 성격: **서비스 기획서.** 서비스가 무엇을 하고, 누가 어떻게 쓰며, 어떤 업무 규칙을 따르는지를 정의한다. 프로그래밍 언어·DB 등 구현 방식은 추후 기술 기획에서 다루고, 그때 검토할 사항만 §20에 정리한다.
> 한 줄 정의: **현장직 팀(건설·판금·전기·목공 등)의 관리자가 프로젝트(현장)에 누구를, 언제, 얼마나 투입했고, 무슨 작업을 했고, 어떤 자재를 썼는지를 수첩처럼 빠르게 기록하고 찾아보는 서비스.** 서로 다른 여러 회사가 함께 이용하며 회사 간 데이터는 완전히 분리된다.
> v2.3의 추가 변경: **이메일 본인 인증**(§6.7)과 **개인정보 보호·고지·정책**(§5.5~§5.13)을 기획에 추가했다.
> v2.2의 큰 변화: ① **직원은 로그인하지 않는다. 관리자만 사용한다.** ② **관리자는 회사당 한 명(팀장)이다.** 현장직은 팀장 한 명이 자기 팀원들과 프로젝트를 수주해서 다니는 구조이므로, 총괄관리자·추가 관리자·권한 단계가 없다. ③ **회사 간 분리는 그대로 유지**한다(서로 다른 두 팀이 각자 쓴다). 이전 버전과의 차이는 §19.1.
> 앞서 정한 범위: 돈 관리(계약 금액·청구·원가·이익·운영비·급여)는 이 서비스가 다루지 않는다.
> 1차 고객: 판금 인테리어 팀(판금 자재를 생산하고 현장에서 직접 설치).

## 1. 서비스 개요

### 1.1 목적
현장직 팀의 관리자는 프로젝트(현장)마다 사람과 자재를 투입하고, 그 기록이 카톡·종이 일보·사진첩·엑셀·머릿속에 흩어져 있다. 이 서비스는 **관리자의 현장 업무 수첩**이다. 관리자가 메모하듯 빠르게 적으면, 서비스가 그것을 **프로젝트·직원·날짜 기준으로 모아서** 보여 준다. 누가 몇 일 투입됐는지(공수), 그날 무슨 작업을 했는지, 어떤 자재가 쓰였는지, 어떤 사진과 자료가 있는지를 한곳에서 찾는다.

### 1.2 대상 고객과 사용자
**팀 단위로 프로젝트(현장)에 투입되어 작업하는 소규모 현장 업체·팀**의 **팀장(관리자)**. **회사마다 관리자는 한 명**이다. 현장직은 팀장이 자기 팀원들과 프로젝트를 수주해서 다니므로 회사(업체)가 곧 한 팀이다. 팀원(직원)은 서비스에 접속하지 않는다.

| 업종 예시 | 프로젝트의 모습 |
|---|---|
| 건설·시공 | 현장별 공사, 여러 공종 팀이 순서대로 투입 |
| 판금·금속 | 자재를 공장에서 가공하고 현장에서 설치 |
| 전기·설비 | 현장별 배선·설비 공사, 점검·보수 |
| 목공·인테리어 | 공간별 시공, 마감·보수 |

**규모 가정**: 회사당 관리자 1명, 기록 대상 팀원(직원) 3~30명, 동시 진행 프로젝트 5~30건. 회사는 서로 무관한 업체들이다(예: A 판금팀, B 전기팀).

**1차 고객 사례 (판금 인테리어)**

| 특성 | 서비스에 미치는 영향 |
|---|---|
| 팀 단위로 현장을 이동하고 인원이 현장마다 바뀐다 | 프로젝트별 투입 인원·기간·공수 기록, 인력 배치 캘린더 |
| 생산(공장 가공)과 설치(현장) 두 작업이 한 프로젝트에 존재 | 작업 구분별 기록·집계 |
| 자재를 만들어 가져가고 남은 것이 생긴다 | 반입·사용·반출·잔량 기록 |
| 관리자가 현장에서 틈틈이 기록하고 나중에 몰아서 정리 | 모바일 우선, 메모함, 소급 입력, 임시 저장, 일괄 입력 |
| 추가 작업·변경 요청이 잦고 말로 합의한다 | 변경·추가 작업 기록과 대화 캡처 보관 |
| 사진이 곧 증빙(시공 전·후, 하자 분쟁) | 프로젝트 사진첩, 작업일지와 연결 |
| 완료 후 보증 기간 중 보수 요청 | 보증 기간·보수 요청 기록 |

### 1.3 핵심 가치
- 관리자가 **수첩처럼 빠르게** 적는다(휴대폰, 일괄 입력, 사진 먼저 찍고 나중에 정리).
- 프로젝트 하나의 **투입·작업·자재·사진·자료·메모**가 한곳에 모인다.
- 직원별·프로젝트별 **정확한 투입 공수**.
- 분쟁·하자 시 꺼내 쓸 수 있는 **기록과 증빙**.
- 회사 간 데이터가 **어떤 경로로도 섞이지 않는** 격리.

### 1.4 범위

| 포함 | 제외 |
|---|---|
| 프로젝트 기본정보(계약일·기간·장소·담당)·상태·진행률 | **금액 관리 전부**: 계약 금액, 청구·입금, 프로젝트 비용·수입, 원가·이익·예산, 회사 운영비·재무 |
| 직원 등록(관리자가 입력), 서류·자격 관리 | **직원 급여·단가·인건비**, 세금, 4대보험 |
| 투입 인원·투입 기간·투입 공수 | **직원 로그인·직원용 화면**(직원 가입·초대·승인 포함) |
| 일자별 작업일지(작업 내용·공수·사진·사용 자재) | 재고·발주·구매 관리, 자재 단가 |
| 프로젝트 메모, 사진, 작업자료(도면·지시서·계약서 등) | 세금계산서, 견적서, 전자결재 |
| 사용 자재(반입·사용·반출·잔량) | 근태(출퇴근) 관리, 공정 간트 차트(초기) |
| 변경·추가 작업 기록, 증빙 보관 | |
| 보증 기간·보수 요청 기록 | |

### 1.5 기획 원칙
1. **수첩처럼 빠르게**: 관리자가 현장에서 쓰기 어려우면 기록이 비고 서비스는 쓰이지 않는다. 자유 메모를 먼저 받고, 구조화는 선택으로 둔다(§14).
2. **프로젝트 중심**: 모든 기록은 프로젝트에 붙고, 프로젝트 화면 하나에서 모든 것을 본다. 직원 카드에서는 그 사람의 모든 투입 이력을 본다.
3. **돈은 다루지 않는다**: 금액 업무는 회사의 세무·회계·급여 방식에 맡기고, 이 서비스는 **공수·자재·사진·자료 같은 사실 기록**을 정확히 남긴다. 필요하면 정산 근거로 내보낼 수 있다(§15.4).
4. **사용자는 회사당 한 명뿐**: 직원 계정·추가 관리자·권한 단계·승인 흐름을 만들지 않아 단순하게 유지한다. 대신 **회사 간 격리와 계정 보안은 철저히** 한다.
5. **쉬운 말**: 현장에서 쓰는 말(현장, 공수, 작업일지, 자재)을 그대로 쓴다. 목록(작업 구분 등)은 회사가 직접 정한다.
6. **소규모·단계적**: 핵심 기록 기능이 실제로 쓰이는 것이 먼저이고, 나머지는 이후 확장한다.

## 2. 확정 사항 요약

| 영역 | 확정 내용 |
|---|---|
| 서비스 정의 | 현장 팀 관리자의 프로젝트 관리 수첩. **돈 관리·급여는 다루지 않음** |
| 사용자 | **관리자만 로그인.** 직원은 관리자가 등록하는 기록 대상이며 로그인·가입·초대·승인 없음 |
| 회사 분리 | 서로 다른 회사의 데이터는 **완전히 분리**. 회사는 내부 고유 식별값으로 관리하고 **로그인 때 입력하지 않으며** 계정에 묶인 회사가 자동으로 정해짐. 같은 주소로 접속 |
| 로그인 수단 | 관리자 계정(인증된 이메일 필수): 별도 아이디 + 카카오·네이버·구글. 나중에 상호 연동 가능(로그인 상태에서만) |
| 회사 시작 | 운영자가 회사와 관리자 계정을 만들고 1회용 초대 링크 전달 → 관리자가 가입 |
| 해지·삭제 | 해지 요청 후 14일 유예 → 데이터 내보내기 → 삭제 |
| 비밀번호 | 본인 변경, 분실 시 **인증된 이메일로 셀프 재설정**, 이메일도 못 쓰면 운영자가 본인 확인 후 복구 |
| 이메일 인증 | 가입 시 이메일 인증 필수, 이메일 변경 시 재인증, 보안·서비스 안내 메일 (§6.7) |
| 개인정보·고지 | 약관·개인정보 동의, 처리방침 공개, 직원 안내문 양식 제공, 처리 위탁 명시, 유출 대응 절차 (§5.5~§5.13) |
| 권한 | **권한 단계 없음.** 관리자 한 명이 모든 기능을 사용 |
| 프로젝트 기본정보 | 계약일, 시작·종료 예정, 실제 시작·완료, 장소, 고객, 담당, 공종, 보증 기간 (§10.2) |
| 프로젝트 상태 | 예정 → 진행 → 완료 → 보증 중 → 종료, 중단·취소 (§10.3) |
| 투입 기록 | 프로젝트 기간 → 직원 투입(투입일자) → 일자별 작업일지(작업 구분·내용·공수·사진·자재). **관리자가 입력하고 저장하면 끝**(컨펌·반려 단계 없음), 수정 이력 보존 |
| 공수 입력 | 비율(1.0/1.5/2.0) 또는 시간(8h+4h=12h). 회사 기본값 + 프로젝트별 재정의. 저장은 분 단위 |
| 프로젝트 메모 | 날짜별 자유 메모·사진·파일을 프로젝트 메모 노트에 기록, 메모함에 먼저 받아 두고 나중에 정리 (§10.9, §14) |
| 사용 자재 | 반입·사용·반출·폐기, 잔량 (§11) |
| 사진·작업자료 | 프로젝트 사진첩, 도면·지시서·계약서 등 자료함. 회사별 분리, 열람 기록 (§12) |
| 변경·추가 작업 | 협의 내용·합의 여부·대화 캡처를 기록 (§10.5) |
| 직원 서류 | 자격증·안전교육 이수증을 관리자가 올리고 만료일 알림 |
| 돈 관련 | 계약 금액, 청구·입금, 비용·수입, 단가·인건비, 이익, 운영비는 **없음** |
| 운영자 기능 | 지인에게만 제공하는 소규모 서비스이므로 운영자가 직접 처리(별도 운영자 콘솔은 필요가 생길 때) |

## 3. 용어 정의

현장에서 쓰는 말을 기본 용어로 쓴다. 회사는 설정에서 표시 이름을 바꿀 수 있다(예: "공수" → "일수").

### 3.1 기본 용어

| 용어 | 정의 |
|---|---|
| 회사 | 서비스를 이용하는 하나의 조직(업체). 현장직에서는 팀장이 이끄는 한 팀이 곧 한 회사. 데이터 분리의 단위 |
| 관리자 | 서비스에 로그인해서 쓰는 사람. **회사당 한 명**(팀장·대표) |
| 직원(팀원) | 관리자가 등록해 두는 인력. 서비스에 로그인하지 않으며 투입·공수 기록의 대상 |
| 직종 | 직원의 기술 분류(판금공, 전기공, 목수, 보통인부 등) |
| 프로젝트 | 하나의 현장·공사·수주 단위 |
| 현장(수행 장소) | 프로젝트의 작업 위치(주소, 건물명) |
| 투입 | 직원을 프로젝트에 배정하는 것(투입 기간) |
| 투입일 | 직원이 실제로 해당 프로젝트에 투입된 날 |
| 공수 | 투입된 일의 분량. **1.0 = 하루**, 0.5 = 반일, 1.5 = 연장 포함 |
| MD | 공수의 합(맨데이). 1.0 = 1인 하루 |
| MM | 맨먼스 = MD ÷ 월 기준일수 |
| 작업일지(작업일보) | 그날 누가 어떤 작업을 했는지 적는 기록 |
| 작업 구분 | 작업의 종류(가공·운반·설치·철거 등). 회사가 정함 |
| 메모 / 메모함 | 프로젝트에 붙이는 자유 메모 / 아직 프로젝트에 연결하지 않고 먼저 받아 둔 메모·사진 |
| 자재 | 프로젝트에 쓰이는 재료(원판, 부자재, 마감재 등) |
| 반입·사용·반출 | 자재가 현장에 들어온 것 / 쓴 것 / 가져간 것 |
| 작업자료 | 도면, 시방서, 작업지시서, 계약서 등 일에 필요한 문서 |
| 변경·추가 작업 | 계약 후 범위·내용이 바뀌거나 늘어난 작업 |
| 보증 기간 | 완료 후 무상으로 보수·관리하는 기간(하자보증 기간 등) |
| 보수 요청 | 보증 기간 중 접수된 수리·보완 요청 |
| 진행률 | 프로젝트 진행 정도(%). 관리자가 입력 |

### 3.2 계산 용어

| 용어 | 정의 |
|---|---|
| 투입 공수 | 저장된 작업일지(임시 저장 제외)의 공수 합 |
| 계획 공수 | 투입 등록 때 정한 예상 공수 |
| 공수 소진율 | 투입 공수 ÷ 계획 공수 |
| 자재 잔량 | 반입 − 사용 − 반출 − 폐기 |
| 임시 저장 / 저장됨 | 작성 중이라 집계에서 제외된 기록 / 저장 완료되어 집계에 반영된 기록 |

## 4. 사용자와 주요 시나리오

### 4.1 사용자 유형

| 사용자 | 하는 일 | 서비스 접속 |
|---|---|---|
| 서비스 운영자 | 회사와 관리자 계정 생성, 계정 문제 지원 | 운영자 전용(회사 업무 데이터는 보지 않음) |
| 관리자(팀장·대표, 회사당 1명) | 프로젝트·직원·투입·작업일지·자재·사진·자료·메모 입력·조회, 회사 설정 | 로그인 |
| 직원 | 서비스에 접속하지 않음. 관리자가 등록하고 기록함 | **없음** |

- 회사는 서로 무관한 업체들이다. A회사 관리자는 A회사 데이터만, B회사 관리자는 B회사 데이터만 본다(§5).

### 4.2 주요 시나리오

**시나리오 1. 새 회사 시작**
1. 운영자가 회사와 관리자 계정을 만든다(1회용 초대 링크 전달).
2. 관리자(팀장)가 가입(아이디 또는 소셜)하고 회사 설정(하루 기준시간, 공수 입력 방식, 작업 구분 목록)을 정한다.
3. 팀원(직원)을 등록한다(이름과 직종만으로도 등록 가능, 나머지는 나중에).

**시나리오 2. 프로젝트 하나의 일생**
1. 계약이 되면 프로젝트를 만든다(프로젝트명, 현장, 고객, 계약일, 시작·종료 예정일, 담당자).
2. 계약서·도면·작업지시서를 자료함에 올린다.
3. 투입할 직원과 기간, 계획 공수를 등록한다. 인력 배치 캘린더에서 겹침을 확인한다.
4. 진행 중에는 매일 작업일지(작업 내용·공수·사진·사용 자재)와 메모가 쌓인다. 변경·추가 작업이 생기면 기록하고 대화 캡처를 남긴다.
5. 완료하면 프로젝트 요약(기간, 직원별 공수, 자재 사용 요약, 사진)이 만들어지고 보증 기간에 들어간다.
6. 보증 기간 중 보수 요청이 오면 기록하고 사진으로 남긴다. 보증이 끝나면 종료한다.

**시나리오 3. 현장에서 틈틈이 메모하고 저녁에 정리 (관리자)**
1. 현장에서 사진을 찍고 한 줄 메모를 남긴다. 프로젝트를 고르지 않아도 **메모함**에 저장된다.
2. 저녁에 프로젝트를 선택하고 오늘 일지를 일괄 입력한다: 투입 인원 목록에서 작업 구분·공수를 한 번에 지정하고, 공통 작업 내용을 한 번 입력한다.
3. 메모함의 사진·메모를 그날 일지와 프로젝트에 연결하고, 쓴 자재를 입력한다.
4. 결근·반일 등 개인별 조정 후 저장한다.

**시나리오 4. 분쟁·문의 대응**
고객이 "그때 이 자리 시공 안 했다"고 주장하면 작업일지의 날짜·인원·작업 내용과 사진, 메모, 대화 캡처를 프로젝트 화면에서 찾아 보여 준다.

**시나리오 5. 월말 공수 확인**
관리자가 이번 달 프로젝트별·직원별 공수를 확인하고 임시 저장된 일지를 정리한 뒤 월 공수를 확정(잠금)한다. 확정된 공수는 엑셀로 내보내 급여·정산 담당(회사 밖)에 전달한다.

## 5. 데이터 격리·보안·개인정보 요구사항

이 장은 **서비스가 지켜야 할 요구사항**이다. 구현 방식(DB 구조, 접근 제어 기술 등)은 추후 기술 기획에서 정하고, 검토할 항목은 §20에 모았다. 개인정보 관련 규정은 법 개정이 잦으므로 이 장은 **기획 수준의 요구사항**이며, 정확한 문구·기한은 공개 전에 전문가와 최신 지침으로 확인한다(§18.2).

### 5.1 회사 간 격리

| # | 요구사항 |
|---|---|
| 1 | 사용자가 볼 수 있는 회사는 **로그인한 계정이 속한 회사 하나뿐**이다. 어떤 화면·목록·검색·내보내기·파일·알림에서도 다른 회사 데이터가 나오지 않는다. |
| 2 | 회사는 로그인 결과로만 결정되고, 사용자가 회사를 입력·선택·변경하는 경로는 없다. |
| 3 | 다른 회사의 데이터를 직접 지정해 요청해도 결과는 **"존재하지 않음"과 구별되지 않아야** 한다(존재 여부도 알려 주지 않음). |
| 4 | A회사 관리자도 B회사 데이터를 볼 수 없다. **운영자도 회사 업무 데이터(직원·프로젝트·사진·자료)를 화면으로 열람하지 않는다.** 지원이 필요할 때는 회사 관리자의 승인과 기록을 거친다. |
| 5 | 회사 식별값은 내부용이며 화면·주소에 노출하지 않는다. |
| 6 | 격리는 서비스가 커지거나 회사별 저장소 분리가 필요해져도 유지된다. |
| 7 | 회사 간 격리는 **자동 점검**(A 계정으로 B의 자료를 요청해 모두 차단되는지)을 모든 기능에 대해 반복 수행할 수 있어야 한다. |

### 5.2 회사 안의 접근 보호
사용자가 회사당 한 명이라 접근 단계는 두지 않고, 계정 하나를 지키는 데 집중한다(§7).
- 계약서·대화 캡처 등 민감 자료와 직원 개인정보는 열람·다운로드를 기록하고, 전체 내보내기는 재인증 후에만 한다.
- 직원 개인정보는 목록에서는 가리고 직원 카드에서만 표시한다.

### 5.3 개인정보
- **주민등록번호·계좌번호는 저장하지 않는 것을 기본**으로 한다.
- 직원 개인정보는 업무에 필요한 최소 항목(이름·생일·직책·입사일·연락처 선택·자격 서류)으로 제한한다.
- 서비스는 고객사 직원 정보를 대신 보관하므로 개인정보 처리방침과 위탁 관계를 갖춘다(§5.5, §5.13).

### 5.4 운영자 권한 분리
- 운영자 계정은 회사 계정과 완전히 분리한다.
- 운영자의 회사 생성·계정 정지·복구 작업은 모두 별도 기록을 남긴다.

### 5.5 개인정보 처리 구조 (누가 어떤 지위인가)

| 정보 | 입력·이용을 정하는 쪽 | 서비스 운영자의 지위 |
|---|---|---|
| 관리자 계정 정보(이메일, 아이디, 소셜 연동값, 접속 기록) | 서비스 운영자가 가입·보안을 위해 직접 수집 | **개인정보처리자**(직접 수집·이용) |
| 직원 정보(이름·생년월일·연락처·자격 서류), 사진, 대화 캡처, 작업일지 | 회사(관리자)가 업무 목적으로 입력·이용 | 회사의 개인정보 처리를 대신 보관하는 **수탁자** |

- 두 번째 경우 **회사와 서비스 운영자 사이의 처리 위탁 관계**를 이용약관(또는 별도 약정)에 명시한다.
- 위 구분은 기획상 가정이며 확정은 법무 확인이 필요하다(§18.2).

### 5.6 수집 항목과 보유 기간

| 대상 | 항목 | 목적 | 보유 |
|---|---|---|---|
| 관리자 | 이메일(필수·인증), 아이디(일반 가입), 비밀번호(복원 불가 형태로 저장), 소셜 연동값, 이름 또는 상호, 연락처 | 가입·본인 확인·복구·서비스 안내 | 해지 후 유예(14일) 뒤 파기, 법정 보존 대상은 분리 보관 |
| 관리자(자동 수집) | 접속 IP, 기기·브라우저 정보, 접속 시각, 쿠키·세션 | 보안, 부정 사용 방지, 접속 기록 보관 의무 | 접속 기록은 법정 기간 보관(§13.1) |
| 직원 | 이름(필수), 직종, 생년월일·연락처·자격 서류·입퇴사일(선택) | 투입·공수 기록, 자격 만료 관리 | 회사가 정한 기간, 퇴사 후 보존기간 경과 시 익명화(§13.3) |
| **수집하지 않는 것** | **주민등록번호, 계좌번호, 건강·종교 등 민감정보** | — | — |

- 항목은 서비스에 꼭 필요한 최소한으로 한다. 새 항목을 추가할 때는 이 표와 처리방침을 함께 고친다.

### 5.7 관리자에게 하는 고지와 동의
- **가입 화면**: 이용약관(필수), 개인정보 수집·이용(필수 항목과 선택 항목 구분)에 동의해야 가입한다. 동의한 일시와 문서 버전을 기록한다.
- 광고성 정보(마케팅) 수신 동의는 **별도 선택**이며 초기에는 받지 않는다. 서비스 이용에 필요한 안내(보증 종료 임박 등)는 정보성 안내로 구분한다.
- **개인정보 처리방침은 항상 볼 수 있게** 공개한다(로그인·가입 화면, 설정 하단). 중요한 변경은 사전에 공지하고 필요하면 다시 동의를 받는다.
- 소셜 로그인으로 가입할 때 제공받는 항목(이메일, 이름 등)을 가입 화면에서 알린다.
- **만 14세 미만은 가입할 수 없다**는 점을 가입 시 확인한다.
- 이메일을 받는 이유(인증·복구·서비스 안내)를 알린다.

### 5.8 팀원(직원)에 대한 안내 — 회사의 책임
직원은 서비스에 접속하지 않지만 관리자가 직원의 정보를 입력한다. 이때 **직원에게 정보 수집·이용을 알리고 필요한 동의를 받는 책임은 회사(관리자)** 에게 있다.
- 서비스는 회사가 직원에게 배포할 수 있는 **직원용 개인정보 수집·이용 안내문(동의서) 양식**을 제공한다(출력·내려받기).
- 직원 등록 화면과 서류 업로드 화면에 안내 문구를 둔다: "주민등록번호·계좌번호는 입력하지 마세요", "서류 사본에 주민등록번호가 보이면 가리고 올리세요".
- 직원이 자신의 정보 열람·정정·삭제를 요청하면 관리자가 처리할 수 있도록 도구를 제공한다(§5.10).

### 5.9 사진·대화 캡처 속 제3자 정보
- 현장 사진에는 사람 얼굴, 차량 번호판, 고객 건물 내부가 찍힐 수 있고, 대화 캡처에는 제3자의 이름·전화번호가 있을 수 있다. 업로드 화면에 **"필요한 범위에서만 올리고, 개인 식별 정보는 가려서 올리세요"** 안내를 둔다.
- 사진에 포함된 위치 정보(촬영 위치)는 증빙에는 도움이 되지만 개인정보가 될 수 있으므로, **다운로드·외부 전달 시 제거하는 옵션**을 둔다(기본값은 §18.1 #12).
- 고객·제3자 정보는 해당 프로젝트의 기록·분쟁 대응 목적으로만 사용한다.

### 5.10 정보주체 권리와 요청 처리
- **관리자 본인**: 설정 화면에서 본인 정보 열람·정정, 이메일 변경, 동의 철회, 해지(삭제)를 직접 할 수 있다. 화면에 없는 요청은 운영자에게 직접 연락해 처리한다(지인에게만 제공하므로 공개 문의 창구는 두지 않는다).
- **직원**: 직원이 요청하면 관리자가 직원 카드에서 **한 사람의 정보 내보내기, 정정, 삭제(퇴사자는 익명화)** 를 처리할 수 있어야 한다.
- 요청 처리 기한은 법정 기한을 따른다(기한은 전문가 확인).
- 해지하면 즉시 로그인이 막히고 14일 유예 후 삭제한다(§6.5). 법정 보존 대상은 분리 보관 후 기간이 지나면 파기한다.

### 5.11 유출 대응
- 유출이 의심되면 **차단 → 원인 파악 → 영향 받는 이용자 통지 → (규모·유형에 따라) 관계 기관 신고 → 재발 방지** 순서로 대응한다. 통지·신고 기한과 대상은 법정 기준을 따른다(§18.2).
- 대응 절차서와 통지문 양식, 연락처를 **미리 준비**해 둔다.
- 접속 기록은 법정 기간 이상 보관한다(§13.1).

### 5.12 책임자와 연락 방법
- **개인정보 보호책임자**는 운영자 본인으로 한다. 서비스는 **지인에게만 제공**하고 이용자가 운영자에게 직접 연락하므로 **공개 문의 이메일은 두지 않는다.** 처리방침에는 "운영자에게 직접 연락"으로 안내하며, 이 정도로 법정 기재 요건이 충족되는지는 공개 전에 확인한다(§18.2).
- 처리방침에는 **수탁·위탁 현황**(클라우드 저장소, 이메일 발송, 소셜 로그인 제공자 등)과 **국외 이전 여부**(서버나 외부 서비스가 해외에 있으면 이전 국가·항목·방법)를 적는다. 어떤 외부 서비스를 쓸지는 기술 기획에서 정해지므로 **기술 선택이 바뀌면 처리방침도 바뀐다**(§20).
- 확장 항목인 "메모 문장 입력 보조(AI)"를 도입하면 입력 내용이 AI 처리에 쓰이는지, 학습에 쓰이는지를 처리방침에 알려야 한다.

### 5.13 필요한 정책·문서 목록

| 문서 | 용도 | 준비 시점 |
|---|---|---|
| 이용약관 | 서비스 이용 조건, 책임 범위, **개인정보 처리 위탁 조항**, 해지 | 소셜 로그인 앱 등록 전 |
| **개인정보 처리방침** | 수집 항목·목적·보유 기간, 수탁·위탁 현황, 국외 이전, 이용자 권리, 보호책임자, 안전조치 | 소셜 로그인 앱 등록 전(대부분의 로그인 제공자가 공개된 처리방침 주소를 요구함) |
| 가입 화면 동의 문구 | 필수·선택 구분, 동의 이력 저장 | 0단계 |
| 직원용 개인정보 안내문(동의서) 양식 | 회사가 직원에게 배포 | 1단계 |
| 업로드 자료 책임 안내문 | 사진·캡처의 제3자 정보 안내 | 2단계 |
| 개인정보 유출 대응 절차서 | 내부 비상 대응(통지문 양식 포함) | 실사용 시험 전 |
| 내부 관리계획(간소) | 접근 통제, 접속 기록, 파기 절차, 담당자 | 실사용 시험 전 |
| 쿠키·접속 정보 고지 | 처리방침 안에 포함 | 0단계 |
| 해지·데이터 반환 안내 | 해지 시 데이터 내보내기·삭제 방법(요금·환불은 없음) | 5단계 |

- 처리방침은 공개된 작성지침(2026년 4월 개정판 확인)과 **실제 처리 내용이 일치**해야 한다. 양식을 그대로 베끼면 실제와 달라져 위험하다.

## 6. 계정·로그인 정책

서비스에 로그인하는 사람은 **회사당 관리자 한 명**(팀장)뿐이다. 직원(팀원)은 계정이 없다.

### 6.1 계정 구조
- **한 회사에 계정은 하나**이고, 한 계정은 한 회사에만 속한다. 회사는 로그인 결과로 자동 결정되며 사용자가 입력하지 않는다.
- 로그인 아이디는 서비스 전체에서 중복될 수 없다.
- **인증된 이메일이 있어야 계정을 쓸 수 있다**(§6.7). 이메일은 로그인 아이디가 아니라 본인 확인·복구·안내용이다.
- 로그인 수단: 별도 아이디·비밀번호, 카카오, 네이버, 구글. 소셜 로그인만 쓰는 계정도 가능하다.
- 일반 아이디로 가입한 관리자도 나중에 **로그인한 상태에서** 소셜 로그인을 연동할 수 있다. 이메일이 같다는 이유만으로 자동 연동하지 않는다. 연동을 해제해도 로그인 수단은 최소 1개 남아야 한다.
- 소셜 로그인 했는데 연결된 계정이 없으면 **가입 불가**로 안내한다. 누구나 가입할 수 있는 공개 가입은 없고, 운영자가 만든 초대로만 가입한다.

### 6.2 회사 시작
```
[운영자]   회사 + 관리자 계정 생성 → 1회용 초대 링크 전달
[관리자]   링크로 접속 → 약관·개인정보 동의 → 아이디 또는 소셜로 가입 → 이메일 인증 → 회사 설정
```
- 초대 링크는 1회용이고 유효기간이 있다. 가입이 끝나면 폐기된다.
- 운영자는 필요 시 관리자 가입을 대신 도울 수 있다.
- 직원 초대·가입·승인, 추가 관리자 초대 절차는 **없다.**

### 6.3 비밀번호와 계정 복구
- 본인이 언제든 비밀번호를 바꿀 수 있고, 바꾸면 다른 기기의 로그인은 모두 풀린다.
- **비밀번호를 잊으면 인증된 이메일로 직접 재설정한다**(§6.7). 대부분의 분실은 운영자 도움 없이 해결된다.
- **이메일도 접근할 수 없게 된 경우**(이메일 계정 분실·퇴사 메일 폐쇄 등)에는 계정이 하나뿐이라 회사가 잠기므로 **운영자가 본인 확인 후 복구**한다(확인 방법은 §18.1 #5). 복구는 임시 비밀번호(또는 재설정 링크)를 **한 번만** 보여 주고 다음 로그인 때 반드시 바꾸게 한다. 운영자도 기존 비밀번호는 볼 수 없다.
- 소셜 로그인만 쓰는 계정은 소셜 계정 쪽 복구를 안내하고, 일반 로그인 추가 방법을 알려 준다.
- 로그인 실패가 반복되면 일정 시간 잠근다.
- **2단계 인증**을 권장한다(계정 하나가 모든 데이터를 열기 때문).

### 6.4 로그인 유지와 기기 관리
현장의 휴대폰에서 쓰므로 자동 로그인(로그인 유지)을 제공한다. 기기 분실에 대비해 **내 로그인 기기 목록과 원격 로그아웃**을 둔다.

### 6.5 계정 해지·삭제
```
해지 요청 → 즉시 로그인 차단 → (14일 유예, 취소하면 복구) → 데이터 내보내기 안내 → 삭제
```
- 관리자가 해지를 요청하면 로그인이 바로 막히고 14일 동안 복구할 수 있다.
- 유예가 끝나면 데이터 내보내기를 제공한 뒤 삭제한다. 보존·익명화 기준은 §13.3을 따른다.
- 운영자가 이용 중단 사유(약관 위반, 보안 문제 등)로 계정을 정지할 수 있으며, 정지 중에도 데이터는 보존된다.

### 6.6 계정 소유자 변경
팀장이 바뀌거나 사무 담당이 대신 써야 하는 경우, 초기에는 **계정 소유자 이전**(운영자 본인 확인 절차)으로 처리한다. 회사 데이터는 그대로 유지된다. 한 계정을 여러 사람이 나눠 쓰는 것은 권장하지 않는다. 추가 사용자 기능은 확장 항목이다(§17).

### 6.7 이메일 본인 인증

**결론: 도입한다.** 사용자가 한 명이라 계정 하나를 잃으면 회사가 잠기므로, 검증된 연락 수단이 있어야 셀프 복구와 보안 알림이 가능하다.

**목적**
1. 실제로 접근 가능한 이메일을 확보한다(오타·허위 이메일 방지).
2. **비밀번호 셀프 재설정**으로 운영자 복구 부담을 줄인다.
3. 보안 알림(새 기기 로그인, 비밀번호·이메일 변경, 해지)과 선택 알림(보증 종료 임박, 일지 미입력)을 보낸다.

**가입 시 인증**
- 이메일을 입력하면 **6자리 인증 코드**(또는 인증 링크)를 보낸다. 유효시간 10분 안팎, 재발송 간격과 시도 횟수를 제한한다.
- **인증이 끝나야 가입이 완료**된다. 일반 아이디 가입은 필수다.
- 소셜 가입은 제공자가 **인증된 이메일을 주면** 그대로 인정한다. 이메일이 없거나(카카오 등 제공 동의 안 함) 인증 표시가 없으면 **별도로 인증**을 받는다.

**이메일 변경**
- 로그인 상태에서 비밀번호를 다시 확인하고, **새 이메일을 인증**해야 바뀐다. 변경 즉시 **이전 이메일로 알림**(되돌리기 링크 포함)을 보낸다.

**비밀번호 재설정**
- 이메일로 **1회용 링크**를 보낸다(짧은 유효시간, 사용 후 폐기). 재설정하면 모든 기기가 로그아웃되고 **완료 알림 메일**이 간다.
- 요청한 이메일이 가입된 주소인지 화면에서 알려 주지 않는다("가입된 주소라면 메일을 보냈습니다"). 계정 존재 여부를 숨기기 위함이다.
- 2단계 인증을 켠 계정은 재설정 때 2단계 인증도 요구한다.

**이메일 알림 (선택)**
- 보증 종료 임박, 오늘 일지 미입력, 월 공수 확정 전 점검을 이메일로도 받을 수 있다(켜고 끔). 광고성이 아닌 **서비스 안내**로 구분하며, 마케팅 메일은 별도 동의 없이는 보내지 않는다(§5.7).

**한계와 보완**
- 이메일 계정이 털리면 서비스 계정도 위험하다. 보완: 2단계 인증 권장, 재설정·변경 알림, 내보내기 재인증(§7.3).
- 이메일 접근 불가 시에는 운영자 복구(§6.3)가 최종 수단이다.
- 메일이 스팸함으로 가거나 지연될 수 있으므로 코드 재발송과 안내 문구가 필요하다.
- 휴대폰 문자·본인확인 인증은 비용과 개인정보 수집 부담이 커서 **넣지 않는다.** 대신 이메일 + (권장) 앱 기반 2단계 인증을 쓴다.

## 7. 사용자 구조와 접근 원칙

### 7.1 사용자는 회사당 한 명
- **권한 단계(역할, 직급별 권한)가 없다.** 관리자 한 명이 모든 기능을 사용한다.
- 직원(팀원)과 고객은 서비스에 접근하지 않는다. 고객 제출용 자료는 작업일보 등을 **출력·내보내기**로 전달한다(고객용 공유 링크는 확장).

### 7.2 접근 원칙
- 다른 회사 자료는 어떤 경로로도 볼 수 없다(§5.1).
- **운영자도 회사 업무 데이터를 열람하지 않는다.** 지원이 필요하면 관리자의 승인과 기록을 거친다.

### 7.3 민감 자료와 내보내기 보호
사용자가 한 명이라 접근을 나누지는 않지만, 계정이 탈취되거나 기기를 분실한 경우를 대비해 다음을 적용한다.
- 계약서·대화 캡처 등은 **민감 자료로 표시**하고 열람·다운로드를 기록으로 남긴다.
- 전체 데이터 내보내기·민감 자료 일괄 다운로드는 **비밀번호 재입력**(또는 재인증) 후 실행하고 기록한다.
- 직원 개인정보(생년월일·연락처)는 목록 화면에서는 가리고 직원 카드에서만 표시한다.
- 로그인 기기 목록·원격 로그아웃(§6.4), 2단계 인증 권장(§6.3)

### 7.4 모든 변경은 기록
저장된 작업일지, 프로젝트 기간·상태, 월 공수 확정은 변경 전 값과 시각을 이력으로 남긴다(§9.1, §13.1).

### 7.5 확장 시 설계
사무 담당·현장소장 등 추가 사용자나 직원 계정이 필요해지면 그때 역할·권한과 작성자 표시를 설계한다(§17). 현재 구조는 그것을 막지 않도록 모든 기록에 작성·수정 시각을 남긴다.

## 8. 직원(인력) 관리

> 직원은 서비스에 로그인하지 않는다. 관리자가 직원 카드를 만들어 두고, 프로젝트마다 투입하고 공수를 기록한다. 급여·단가는 다루지 않는다.

### 8.1 직원 등록
- 관리자가 직접 등록한다. **이름과 직종만으로도 등록**할 수 있고(일용·협력 인력용), 나머지는 나중에 채운다.
- 계정·초대·승인은 없다.

### 8.2 기본 정보
- 이름, 생년월일, **직책**(표시용: 반장, 기공, 조공 등), **직종**, 입사일, 퇴사일, 상태(재직 / 휴직 / 퇴사)
- **구분**: 정직원 / 계약직 / 일용 / 협력(외부) 인력 중 선택. 목록과 필터용 표시이며 계산에는 쓰지 않는다. 회사가 목록을 바꿀 수 있다.
- 연락처(선택), 메모
- **주민등록번호·계좌번호는 저장하지 않는다.**

### 8.3 직종
- **직종**은 회사가 정한다(프리셋 예: 판금공, 설치공, 용접공, 전기공, 목수, 보통인부, 현장소장, 사무). 직종별 투입 공수를 집계할 수 있다.
- 회사가 곧 한 팀이므로 별도의 팀 분류는 두지 않는다. 직원을 묶어 부르고 싶으면 **직종**이나 "자주 쓰는 인원 묶음"(예: 설치조)을 쓴다.

### 8.4 서류·자격
- 자격증(용접·판금 기능사, 전기기능사 등), 안전교육 이수증, 건강검진 서류 등을 **관리자가 직원 카드에 올린다.**
- 항목: 종류, 취득일, **만료일(만료 임박 알림)**, 업로더
- 프로젝트에서 **필요한 자격**(예: 용접 자격 필수)을 정해 두면, 투입 배정 때 자격이 없거나 만료된 직원을 경고한다.

### 8.5 직원 카드 화면
- 기본정보, 서류·만료 상태
- **투입 이력**: 프로젝트별 투입 기간, 투입일수, 총 공수(MD), 최근 투입
- 이번 달·올해 총 공수
- 메모(관리자용 자유 메모: "이 사람은 용접 잘함" 등)

### 8.6 퇴사 처리
- 상태를 퇴사로 바꾸면 신규 투입·일지 입력에서 제외되고, **과거 투입·작업 이력은 그대로 남는다.**
- 재입사하면 같은 직원 카드를 다시 재직으로 바꾼다.
- 개인정보 보존·익명화는 §13.3을 따른다.

## 9. 투입·작업일지

### 9.1 흐름

```
프로젝트 (시작일 ~ 종료일)
  └ 투입 등록      직원 + 투입 기간 (프로젝트 기간 안) + 계획 공수
       └ 작업일지   투입일별: 작업 구분 + 작업 내용 + 공수 + 사진 + 사용 자재
            (관리자가 입력)   임시 저장 → 저장            (월 공수 확정은 선택, §13.2)
```

1. 관리자가 프로젝트 시작일·종료일을 정하고 직원을 투입 등록한다(투입 기간, 계획 공수).
2. 투입일마다 작업일지를 입력한다. 직원별로 하나씩 적지 않고 **그날 프로젝트 단위로 일괄 입력**한다(§9.3).
3. **저장하면 끝**이다. 승인·반려 단계는 없다. 작성 중인 것은 임시 저장해 두었다가 나중에 마무리한다.
4. 저장된 일지는 언제든 수정할 수 있고, 수정하면 변경 전 값과 시각이 기록된다(분쟁 때 기록의 신뢰성을 보이기 위함).

### 9.2 작업일지 항목

| 항목 | 설명 |
|---|---|
| 작업 일자 | 프로젝트 기간 안의 날짜 |
| 투입 직원 | 직원(여러 명) |
| 작업 구분 | 회사가 정한 목록(예: 생산·가공 / 운반 / 설치 / 철거 / 배선 / 마감 / 기타) |
| 작업 구역(선택) | 층·호실·동 등 작업 위치 |
| 작업 내용 | 자유 텍스트 |
| 공수 | §9.5 방식으로 직원별 입력. 내부적으로는 분 단위로 저장 |
| 사용 자재 | 그날 사용·반입·반출한 자재(§11). 일지 화면에서 바로 추가 |
| 사진 | 여러 장 첨부(§12), 메모함에서 가져오기 |
| 날씨·특이사항 | 선택(우천 중단, 자재 지연 등) |
| 변경·사후 표시 | 변경·추가 작업 / 사후 작업이면 표시 |
| 작성·수정 시각 | |
| 상태 | 임시 저장 / 저장됨 |

- **작업 내용·사진·자재는 "프로젝트의 그날"에 붙고**, 공수만 직원별로 다르다. 같은 날 같은 프로젝트에 여러 직원이 투입돼도 공통 내용은 한 번만 입력한다.

### 9.3 일괄 입력

```
프로젝트 + 일자 선택 → 투입 직원 목록 → 작업 구분·공수 일괄 지정
→ 공통 작업 내용·사용 자재·사진 1회 입력 → 개인별 조정(반일·연장·결근) → 저장
```
- "어제와 동일" 복사, 여러 일자 한꺼번에 입력을 지원한다.
- **투입 등록이 안 된 직원**을 일지에 넣으면 투입 등록을 자동으로 추가할지 묻는다(수첩처럼 빨리 적기 위해).
- 직원을 한 번에 불러온다("전원", "지난번과 동일", 자주 쓰는 인원 묶음).

### 9.4 규칙
- **프로젝트 기간 밖의 일자는 입력할 수 없다.** 기간이 늘어나면 관리자가 프로젝트 기간을 연장한 뒤 입력한다(연장 이력이 남는다).
- **소급 입력을 허용한다.** 작업일과 작성일 차이가 크면 "지연 입력"으로 표시만 한다. 월 공수가 확정된 달은 재오픈해야 한다.
- **공수 집계에는 저장된 일지만 반영**하고 임시 저장은 별도 표시한다.
- 같은 직원의 하루 합계 공수가 기준을 넘으면 경고한다(예: 프로젝트 A 1.0 + B 1.0 = 2.0). 퇴사·휴직 직원이나 자격이 만료된 직원을 넣으면 경고한다.
- 직원은 서비스에 접속하지 않으므로 **직원 본인 확인 단계는 없다.** 관리자 기록이 곧 근거이므로 수정 이력과 감사 기록(§13.1)으로 신뢰성을 보완한다.

### 9.5 공수 입력 방식

회사 기본값을 정하고 **프로젝트별로 다르게 지정**할 수 있다(프로젝트 설정이 없으면 회사 기본값).

| 방식 | 입력 예 | 설명 |
|---|---|---|
| 비율 | 1.0 / 1.5 / 2.0 (0.5 단위 등) | 하루 = 1.0. 연장 근무를 1.5로 입력하는 회사에 적합 |
| 시간 | 8시간 + 4시간 = 12시간 | 실제 시간 입력. 시간 단위로 관리하는 회사 |

- **하루 기준시간**은 회사 설정(기본 8시간), 프로젝트별 재정의 가능.
- 저장은 항상 분 단위이므로 방식이나 기준시간을 나중에 바꿔도 과거 기록은 변하지 않는다.
- 비율 입력 시 1.5는 "기준시간 × 1.5"로 환산된다(8시간 기준 12시간).

```
공수(MD) = 투입 시간 ÷ 하루 기준시간      (1.0 = 하루)
MM(맨먼스) = MD ÷ 월 기준일수               (월 기준일수는 회사 설정, 예: 22일)
```

**예시**: 김OO이 A 프로젝트에 3월 한 달 동안 투입일 20일, 그중 연장 2일(1.5)이면 MD = 18 × 1.0 + 2 × 1.5 = 21.0, MM = 21.0 ÷ 22 ≈ 0.95.

### 9.6 집계
- **프로젝트 → 직원별**: 투입일수, 총 공수(MD), MM, 계획 대비 실제(공수 소진율)
- **프로젝트 → 작업 구분별**: 가공 공수와 설치 공수 분리
- **프로젝트 → 기간별**: 주·월 단위 공수 추이
- **직원 → 프로젝트별**: 어느 프로젝트에 몇 공수를 썼는지(직원 카드)
- **일자별 타임라인**: 그날 누가 어떤 작업을 했는지, 작업 내용 검색
- 월 단위 **공수 확정**(§13.2) 후 엑셀 내보내기

### 9.7 인력 배치 캘린더
- 직원 × 날짜 표에 **어느 프로젝트에 투입되는지**를 보여 준다. 한 사람이 같은 날 두 프로젝트에 겹쳐 배정되면 경고한다.
- 휴직·휴가·자격 만료 표시, "이번 주 비는 사람" 확인
- 배치 변경은 이력으로 남긴다.

## 10. 프로젝트 관리

이 장이 서비스의 중심이다. 프로젝트 하나에 대해 **기본정보 → 상태·일정 → 투입·작업 → 자재·사진·자료 → 변경·추가 작업 → 보증·보수**를 관리한다.

### 10.1 고객·협력업체 명부
- 고객(발주처, 원청), 협력업체(타 공종 팀, 외주), 자재 공급처를 간단한 명부로 관리한다.
- 항목: 구분, 상호, 담당자·연락처, 메모. 프로젝트의 고객·협력업체와 자재 반입처로 연결한다.
- 금액·거래 내역은 관리하지 않는다.

### 10.2 프로젝트 기본정보

등록 때는 최소 항목만 받고, 진행에 따라 채운다.

| 구분 | 항목 | 설명 | 필수 시점 |
|---|---|---|---|
| **식별** | 프로젝트 코드 | 회사별 자동 번호(예: 2026-012). 수정 불가 | 자동 |
| | 프로젝트명 | | 등록 |

### 10.3 프로젝트 상태

```
예정 → 진행 → 완료 → 보증 중 → 종료
         ↕ 중단
   (예정·진행·중단) → 취소
```

| 상태 | 의미 | 대표적 행동 |
|---|---|---|
| **예정** | 계약됐고 아직 시작 전 | 기본정보·자료·투입 계획 |
| **진행** | 실제 작업 중 | 작업일지·자재·사진·변경 기록 |
| **중단** | 고객 사정·우천·자재 지연 등으로 일시 중지(재개 가능) | 사유·중단일 기록, 투입 중지 |
| **완료** | 작업을 마치고 인도함 | 프로젝트 요약 확인 |
| **보증 중** | 보증 기간 중 | 보수 요청 기록, 사후 작업 |
| **종료** | 모든 관리가 끝남. 잠금 | 조회만 |
| **취소** | 계약이 없어지거나 진행하지 않기로 함 | 사유 기록, 이미 쌓인 기록은 보존 |

- 상태 이름은 회사가 표시 이름을 바꿀 수 있다.
- 보증 기간이 0이면 **완료에서 바로 종료**할 수 있다.

| 투입 배정 | ○ | ○ | △ 관리자 확인 | ✕ | △ 사후 작업만 | ✕ | ✕ |

| 자재 기록 | ○ 반입만 | ○ | ○ | ○ | ○ | ✕ | ✕ |

**전환 조건**

| 전환 | 필요한 조건 | 자동으로 하는 일 |
|---|---|---|
| 예정 → 진행 | 실제 시작일 | 작업일지 입력 시작 |
| 진행 → 중단 | 중단일, 사유 | 신규 투입 차단, 중단 목록에 표시 |
| 중단 → 진행 | 재개일 | 종료 예정일이 지났으면 기간 연장 안내 |
| 진행 → 완료 | 실제 완료일. **임시 저장된 작업일지 확인**, 진행률 100% 안내, 남은 자재 확인 | **프로젝트 요약 생성**(§10.7), 보증 종료 예정일 계산 |
| 완료 → 보증 중 | 프로젝트 요약 확인 | 이후 작업은 "사후 작업"으로 구분 |
| 보증 중 → 종료 | 보증 기간 종료(또는 사유 기록 후 조기 종료), 미처리 보수 요청 없음, 임시 저장 일지 없음 | 프로젝트 잠금 |

- 종료된 프로젝트는 관리자가 **재오픈**할 수 있고, 사유가 기록된다.
- 모든 상태 변경은 변경자·시각·사유와 함께 이력으로 남는다.

### 10.4 일정과 진행

- **진행률(%)**: 담당자가 수시로 입력한다(이력 저장). 선택으로 작업 구분별 진행률(가공 80%, 설치 30%)도 입력한다.
- **공수 소진율**: 투입 공수 ÷ 계획 공수. 진행률보다 공수 소진율이 크게 앞서면 경고한다(공수가 일의 진척보다 빨리 쓰이고 있다는 신호).
- **일정 지연**: 종료 예정일이 지났는데 완료되지 않은 프로젝트, 진행률이 일정 대비 뒤처진 프로젝트를 목록에서 표시한다.
- 경고 기준(예: 공수 소진율 80% / 100%)은 회사가 정한다.

**예시**: 계획 공수 80MD, 지금까지 투입 56MD(소진율 70%). 진행률은 45%다. 현재 속도로 끝내려면 56 ÷ 0.45 ≈ 124MD가 필요하므로 계획을 크게 넘는다는 경고가 뜬다.

### 10.5 변경·추가 작업 기록

계약 후 범위나 내용이 바뀌거나 추가되는 일을 **기록으로 남긴다.** 현장에서는 말로 합의하고 먼저 작업하는 일이 많아, 나중에 "누가 언제 요청했는가"가 분쟁의 핵심이 된다. 금액은 기록하지 않는다.

| 항목 | 설명 |
|---|---|
| 일자·요청자 | 누가 요청했는가(고객 담당자, 현장소장 등) |
| 내용 | 무엇이 바뀌거나 추가되는가 |
| 상태 | **협의 중** / **합의됨** / 철회 |
| 관련 작업 | 이 변경 때문에 쓴 공수·자재를 작업일지에 "변경 작업" 표시로 연결 |
| 증빙 | 대화 캡처, 합의서, 사진 첨부(민감 자료) |

- 변경 작업으로 표시된 일지의 공수·자재는 프로젝트 화면에서 **"변경·추가 작업으로 쓴 공수·자재"** 로 따로 합계가 나온다(나중에 정산·협의할 때 근거).
- 협의 중인 상태로 오래 남은 건은 알림으로 표시한다.

### 10.6 보증 기간과 보수 요청

완료 후 일정 기간 무상으로 보수하는 약속을 **보증 기간**이라 한다(하자보증 기간 등).

**설정**

| 항목 | 설명 |
|---|---|
| 보증 기간 | 개월 수(예: 12개월, 24개월). 0이면 보증 없음. 회사 기본값 사용 가능 |
| 시작 기준 | 실제 완료일 / 고객 검수일 / 직접 지정. 기본은 실제 완료일 |
| 종료 예정일 | 시작일 + 보증 기간으로 자동 계산, 필요하면 수정(사유 기록) |
| 보증서 | 보증서(보증증권 등)를 제출한 경우 파일·만료일 관리 |
| 보증 연장 | 재보수로 보증이 늘어나면 종료 예정일 조정(사유·이력) |

**보수 요청 기록**
- 항목: 접수일, 요청자, 내용, 위치(구역), 상태(접수 / 처리 중 / 완료 / 보류), 처리일, 투입 인원·공수, 사용 자재, 사진(전·후)
- 보수 작업은 작업일지에 **"사후 작업"** 으로 입력하고 보수 요청 건과 연결한다. 프로젝트 화면에서 **사후 작업에 쓴 공수·자재**가 따로 합계된다.

**알림**: 보증 종료 예정 60일 / 30일 / 7일 전, 종료 당일, 미처리 보수 요청 경과, 보증서 만료 임박.

### 10.7 프로젝트 요약 (완료 리포트)

완료 처리 시 자동 생성하고, 보증 종료 시 갱신한다.

- 기본정보: 고객, 현장, 계약일, 계획·실제 기간
- 투입 요약: 인원별·작업 구분별 공수, 총 MD·MM, 계획 대비
- 자재 요약: 자재별 반입·사용·반출·잔량(§11.4)
- 변경·추가 작업 목록과 그에 쓴 공수·자재
- 사진 대표 컷, 자료 목록
- 사후 작업(보수 요청 건수, 공수, 자재)
- 인쇄·PDF·엑셀 내보내기(권한 필터 적용)

### 10.8 프로젝트 화면 구성 (상세 화면 탭)

| 탭 | 내용 |
|---|---|
| 개요 | 상태, 기본정보 요약, 핵심 지표(기간, 진행률, 투입 공수·소진율, 투입 인원, 자재 요약), 경고 |
| 기본정보 | §10.2 항목 편집, 변경 이력 |
| 투입·작업일지 | 투입 인원, 일자별 작업일지, 인원별·작업 구분별 집계, 인력 배치 |
| 자재 | 반입·사용·반출 내역, 자재별 잔량 |
| 사진 | 사진첩(작업 전·중·후, 구역별) |
| 메모 | 날짜별 메모 노트(§10.9) |
| 작업자료 | 도면·지시서·계약서 등 문서함 |
| 변경·추가 작업 | §10.5 목록 |
| 보증·보수 | 보증 기간, 보수 요청 목록 |
| 이력 | 상태·기간·담당 변경 이력 |

- 프로젝트 목록: 상태·담당자·고객·공종·기간·경고 여부로 검색·필터, "종료 임박 / 공수 소진율 높은 순 / 최근 일지 없음" 정렬.
- 권한이 없는 탭·항목은 보이지 않는다.

### 10.9 프로젝트 메모 노트

프로젝트에 붙는 **관리자의 자유 메모장**이다. 정해진 양식에 들어가지 않는 내용(통화 내용, 현장 지시, 이슈, 해야 할 일)을 날짜별로 쌓는다.

- 항목: 날짜, 내용(자유 텍스트), 태그(협의 / 지시 / 이슈 / 할 일 / 기타), 사진·파일 첨부
- **메모함**: 프로젝트를 정하지 않고 먼저 저장한 메모·사진이 모이는 곳이다. 나중에 프로젝트와 작업일지에 연결하거나 삭제한다(§14).
- 메모를 **변경·추가 작업 기록(§10.5)으로 승격**하거나 **보수 요청(§10.6)으로 전환**할 수 있다. 같은 내용을 다시 쓰지 않는다.
- "할 일" 태그 메모는 완료 체크를 하고, 미완료 건은 대시보드에 모아 보여 준다.
- 프로젝트 안 검색: 작업일지·메모·변경 기록·자료 이름을 한 번에 검색한다.

## 11. 사용 자재 관리

### 11.1 목적
프로젝트에 **어떤 자재가 언제 얼마나 들어오고 쓰이고 나갔는지**를 기록한다. 가격·구매·재고는 다루지 않는다. 목적은 (1) 분쟁 시 사용 내역을 증명하고, (2) 남은 자재를 파악하고, (3) 다음 프로젝트 견적·준비에 참고할 실사용량을 쌓는 것이다.

### 11.2 자재 목록
- 자재 목록은 회사가 관리한다: 자재명, 규격, **기본 단위**(장·개·m·㎡·kg·박스 등), 분류(원자재 / 부자재 / 마감재 / 소모품), 별칭.
- **입력하다가 목록에 없으면 그 자리에서 새로 추가**할 수 있다(현장에서 목록 관리 때문에 입력이 막히지 않게). 이후 관리자가 비슷한 이름을 하나로 합칠 수 있다.
- 최근 사용 자재와 자주 쓰는 자재를 위에 보여 준다.
- 같은 이름이라도 규격이 다르면 별도 자재로 본다(예: 아연도강판 0.8T / 1.0T).

### 11.3 자재 기록 항목

| 항목 | 설명 |
|---|---|
| 일자 | 기록 날짜 |
| 프로젝트 | 어느 프로젝트의 자재인가 |
| **구분** | **반입**(현장에 들어옴) / **사용** / **반출**(가져감, 반납) / **폐기** |
| 자재·수량·단위 | 자재 목록에서 선택, 수량 입력 |
| 작업 구분·구역 | 사용한 작업과 위치(선택) |
| 출처·행선지 | 반입처(공장, 공급처 명부, 직접 입력) / 반출처 |
| 작업일지 연결 | 그날 작업일지와 연결(일지 화면에서 입력하면 자동) |
| 변경·사후 표시 | 변경·추가 작업 / 사후 작업에 쓴 자재면 표시 |
| 첨부 | 자재 사진, 거래명세표(민감 자료로 열람 제한 가능) |
| 메모 | |

### 11.4 잔량
```
잔량 = 반입 − 사용 − 반출 − 폐기       (자재별, 프로젝트별)
```
- 잔량이 마이너스면 반입 기록 누락일 수 있으므로 경고한다.
- 프로젝트를 **완료**할 때 잔량이 남은 자재를 보여 주고, 처리 방법(반출 / 폐기 / 현장 보관 / 다음 프로젝트로 이관 메모)을 남기도록 안내한다.
- 프로젝트 간 이관은 초기에는 한쪽 프로젝트에서 반출, 다른 쪽에서 반입으로 입력한다(자동 이관은 확장).

**예시**: 아연도강판 1.0T — 반입 100장, 사용 72장, 반출 10장, 폐기 3장 → 잔량 15장.

### 11.5 계획 자재 (선택)
프로젝트에 예상 소요량을 입력하면 사용량과 비교한다(예: 계획 80장 대비 사용 72장). 초기에는 선택 기능이고, 입력하지 않아도 모든 기능은 동작한다.

### 11.6 입력 편의
- 작업일지 화면 안에서 바로 자재를 추가한다(별도 메뉴로 가지 않음).
- "어제와 동일", 최근 사용 자재 한 번 터치 추가, 수량 큰 숫자 입력
- 자재 사진을 찍어 두면 기록에 연결된다.
- 한 번에 여러 자재를 입력하는 목록형 입력

### 11.7 집계
- 프로젝트별 자재 사용 합계와 잔량
- 자재별 프로젝트별 사용량(같은 자재를 어느 프로젝트에 얼마나 썼는지)
- 변경·추가 작업에 쓴 자재, 사후 작업에 쓴 자재
- 엑셀 내보내기(권한 필터 적용)

### 11.8 범위 밖
**자재 단가·구매·발주·재고 관리는 하지 않는다.** 회사 창고·공장 재고를 관리하는 기능은 필요해지면 확장(§17)으로 검토한다.

## 12. 사진·작업자료·증빙

### 12.1 공통 원칙
- **업로드**: 형식·용량 검증, 악성 파일 점검
- **다운로드**: 권한 확인 후 짧은 시간만 유효한 방식으로 제공, 민감 자료는 다운로드 기록
- **무결성**: 업로드 시각·업로더·파일 고유값을 함께 저장해 원본임을 입증한다. 파일은 **덮어쓰지 않고 새 버전으로 추가**한다.
- **삭제**: 소프트 삭제 + 보존 기간, 완전 삭제는 관리자가 확인 절차를 거쳐서만
- 회사별 저장 용량 한도(운영자가 서버 용량에 맞춰 정함)

### 12.2 작업 사진

현장 사진은 이 서비스의 핵심 증빙이다.

| 항목 | 설명 |
|---|---|
| 구분 | 작업 전 / 작업 중 / 작업 후 / 하자·보수 / 자재 / 안전 / 기타 |
| 구역 | 층·호실·동 등 작업 위치 태그(선택) |
| 촬영·업로드 일시 | 촬영일(사진 정보 또는 직접 지정)과 업로드 시각을 함께 보관 |
| 설명 | 짧은 메모(선택) |
| 연결 | 작업일지, 자재 기록, 변경·추가 작업, 보수 요청에 연결 |
| 대표 사진 | 프로젝트 대표 컷 지정 |

- **휴대폰 카메라로 바로 촬영·업로드**하고, 여러 장을 한꺼번에 올린다. 자동 압축·썸네일, 실패 시 재시도.
- 사진첩 보기: 날짜별 / 구역별 / 구분별, **작업 전·후 비교** 보기
- 선택한 사진을 묶어 내려받기(제출용), 사진이 들어간 작업일지 출력
- 위치 정보 등 사진에 포함된 개인정보의 처리 방침은 §18에서 정한다.

### 12.3 작업자료 (문서함)

프로젝트에 필요한 문서를 한곳에 모은다.

| 분류 | 예시 |
|---|---|
| 도면 | 시공도, 가공도, 평면도 |
| 시방·사양 | 시방서, 자재 사양서 |
| 작업지시 | 작업지시서, 작업 순서, 현장 유의사항 |
| 계약·행정 | 계약서, 변경 합의서, 공문 |
| 안전·검사 | 안전 점검표, 검사·확인서, 준공 서류 |
| 기타 | |

- **버전 관리**: 도면처럼 개정되는 문서는 같은 문서의 새 버전으로 올리면 **최신본이 기본으로 보이고 이전본은 보존**된다(개정일·사유 표시).
- **열람 범위**: 문서마다 "일반 자료 / 민감 자료"를 구분한다. 민감 자료는 열람·다운로드 기록을 남기고 내보낼 때 한 번 더 확인한다(§7.3). 계약서는 기본적으로 민감 자료다.
- **자주 보는 자료 고정**: 현장에서 자주 여는 도면은 프로젝트 첫 화면에 고정해 바로 연다.
- 휴대폰에서 열람할 수 있는 형식(PDF·이미지 우선)을 우선 지원한다. 지원하지 않는 형식(설계 파일 등)은 내려받기만 한다.
- 완전 오프라인 열람은 확장(§17).

### 12.4 증빙 (대화 캡처·합의서)
- 고객과의 대화 캡처, 변경 합의서, 구두 합의를 정리한 메모를 **변경·추가 작업 기록**(§10.5)과 프로젝트에 붙인다.
- **민감 자료**로 분류해 열람 권한을 별도로 두고, 열람·다운로드 기록을 남긴다.
- 캡처 이미지는 업로드 시각·업로더를 함께 보관해 사후 변조가 없었음을 보일 수 있게 한다.

### 12.5 직원 서류
자격증·안전교육 이수증 등은 직원 서류(§8.4)로 관리하며, 열람·다운로드는 기록으로 남긴다(§7.3).

## 13. 감사·확정·데이터 정책

### 13.1 감사 기록
- 대상: 로그인 성공·실패, 비밀번호 변경, 민감 자료 열람·다운로드, 내보내기, 월 공수 확정·재오픈, 프로젝트 상태·기간 변경, 저장된 작업일지의 수정·삭제(변경 전 값 포함)
- 기록은 **수정·삭제할 수 없다.** 회사 기록과 운영자 기록은 분리한다.
- 접속 기록의 보관 기간은 개인정보 관련 기준을 확인해 정한다(§18.2).

### 13.2 월 공수 확정
공수 기록이 급여·정산의 근거로 쓰이므로, 월 단위로 **확정(잠금)** 하는 절차를 둔다.

- 확정 전 **임시 저장된 작업일지**가 있으면 목록으로 경고하고, 저장 처리하거나 확인 후 확정한다.
- 확정되면 그달의 작업일지(공수)는 수정할 수 없다. 정정은 **재오픈(사유 기록)** 으로만 한다.
- 확정 시점의 **하루 기준시간과 월 기준일수를 그 시점 값으로 고정**한다.
- 확정은 선택 기능이며, 쓰지 않는 회사는 저장된 기록만으로 운영한다.

### 13.3 보존·삭제 정책

| 대상 | 방침 |
|---|---|
| 계약서·변경 합의서·증빙 | 분쟁 대비 충분한 기간 보관(기간은 **전문가 확인**) |
| 작업일지·사진·자료 | 프로젝트 종료 후 회사가 정한 기간 보관, 이후 삭제 또는 내보내기 |
| 근로 관련 기록(투입 공수 등) | 법정 보존기간 이상(**노무사 확인**) |
| 접속 기록 | 관련 기준에 따라 보관 |
| 퇴사 직원 개인정보 | 보존기간 경과 후 **익명화**(이름을 식별 불가 값으로 바꾸고 공수 통계는 유지) |
| 로그인 정보 | 계정 삭제 시 즉시 파기 |
| 회사 해지 | 유예 기간 → 데이터 내보내기 제공 → 삭제·익명화 |

## 14. 사용성 요구사항 (수첩처럼 빠르게)

이 서비스의 모든 기록은 관리자의 입력에서 시작한다. 관리자가 현장에서 틈틈이 쓰지 못하면 나머지 기능은 의미가 없다. 관리자의 가장 흔한 사용 장면은 **현장에서 휴대폰으로 사진과 한 줄 메모를 남기고, 저녁에 정리하는 것**이다.

| 요구사항 | 내용 |
|---|---|
| **모바일 우선** | 휴대폰 한 손 조작. 장갑을 낀 손으로도 누를 수 있는 큰 버튼, 햇빛 아래서도 읽히는 큰 글자·높은 대비 |
| **항상 보이는 빠른 추가 버튼** | 어느 화면에서든 한 번에 "메모 / 사진 / 오늘 일지 / 자재" 추가 |
| **메모함(받은 메모함)** | 프로젝트를 고르지 않아도 사진·메모를 먼저 저장하고 나중에 프로젝트·일지에 연결. 정리 안 된 건수를 표시 |
| **자유 메모 우선** | 구조화 항목(공수·자재)은 선택이다. 한 줄 메모만 적어도 기록으로 남는다 |
| **입력 시간 목표** | 하루 일지 일괄 입력(직원·공수·작업 내용·자재·사진)을 **3분 안에** 마칠 수 있어야 한다 |
| **일괄 입력** | 프로젝트·일자 선택 → 직원별 공수 일괄 입력, 직원 한 번에 불러오기(§9.3) |
| **빠른 입력** | "어제와 동일" 복사, 기본값 자동 채움, 여러 일자 한꺼번에, 자주 쓰는 자재·작업 구분·직원 우선 표시, 최근 사용 먼저 |
| **사진** | 카메라로 바로 촬영·업로드, 한 번에 여러 장, 자동 압축, 실패 시 재시도 |
| **임시 저장** | 통신이 불안정한 곳(지하·신축 현장)에서도 입력이 유실되지 않도록 기기에 임시 저장 후 전송 |
| **소급 입력** | 나중에 몰아서 입력해도 되고, 지연 입력은 표시만 한다 |
| **로그인 유지** | 자동 로그인, 간편 로그인(소셜) |
| **찾기** | 프로젝트·직원·메모·자료를 한 검색창에서 찾는다 |
| **알림** | 오늘 일지 미입력, 정리 안 된 메모함, 보증 종료 임박, 자격·계약 만료를 화면에 표시(외부 알림은 이메일부터, 나머지는 후순위) |

완전한 오프라인 동작은 확장 항목이다. 초기에는 임시 저장과 재전송으로 유실만 막는다.

## 15. 화면·메뉴 구조, 대시보드, 알림, 리포트

### 15.1 메뉴 구조

관리자 한 명이 모든 메뉴를 쓴다.

```
홈 (대시보드 + 빠른 추가 버튼 + 메모함)
프로젝트
  ├ 프로젝트 목록 / 등록
  ├ 프로젝트 상세 (개요·기본정보·투입·작업일지·자재·사진·작업자료·메모·변경 작업·보증·이력)
  └ 보증·보수 현황 (보증 중 프로젝트, 종료 임박, 미처리 보수 요청)
작업일지
  ├ 오늘 작업일지 (일괄 입력)
  └ 월 공수 확인·확정
직원
  ├ 직원 목록·카드 (기본정보·서류·투입 이력)
  ├ 인력 배치 캘린더
  └ 직종
자재
  ├ 프로젝트별 자재 현황
  └ 자재 목록 관리
고객·협력업체
설정
  ├ 회사 설정 (하루 기준시간·월 기준일수·공수 방식·보증 기본값·경고 기준)
  ├ 표시 이름·목록 관리 (작업 구분·공종·자재 분류·직종·자격 종류)
  └ 기록 조회 (로그인·내보내기·수정 이력)
내 정보 (비밀번호 변경, 소셜 연동, 로그인 기기)
```

- 운영자 화면은 별도이며 회사 업무 데이터를 보여 주지 않는다(§5.1).

### 15.2 홈 대시보드

| 위젯 | 내용 |
|---|---|
| 메모함 | 정리 안 된 메모·사진 건수와 바로가기 |
| 오늘의 투입 | 오늘 어느 프로젝트에 몇 명이 나갔는지, 일지 미입력 프로젝트 |
| 진행 프로젝트 | 진행·예정·중단 건수와 목록, 경고 표시 |
| 이번 주 인력 | 배치 캘린더 요약, 겹침·공백 |
| 위험 프로젝트 | 공수 소진율이 진행률보다 빠르거나 종료 예정일이 지난 프로젝트 |
| 할 일 | "할 일" 태그 메모 중 미완료, 임시 저장 일지, 월 공수 미확정 |
| 보증 종료 임박 | 60일 이내 종료 예정, 미처리 보수 요청 |
| 만료 임박 | 직원 자격·서류, 계약직 계약 |

### 15.3 알림 규칙 (초기: 화면 표시)

| 이벤트 | 시점 |
|---|---|
| 오늘 투입 프로젝트에 일지 미입력 | 투입일 저녁(회사 설정 시각) |
| 메모함에 정리 안 된 항목 | 3일 이상 방치 시 |
| 공수 소진율 80% / 100% 도달 | 도달 시 |
| 진행률 대비 공수 소진 과다 | 진행률 갱신 시 |
| 프로젝트 종료 예정일 경과(미완료) | 경과 다음 날 |
| 같은 날 중복 투입 | 투입 배정·일지 저장 시 |
| 협의 중 변경 작업 장기 방치 | 7일 경과 시 |
| 보증 종료 예정 | 60일 / 30일 / 7일 전, 종료 당일 |
| 미처리 보수 요청 | 접수 후 3일 경과 시, 이후 주 1회 |
| 보증서 만료 | 30일 전 |
| 계약직 계약·자격·서류 만료 | 30일 전 |
| 월말 점검 | 매월 말 3일 전 (임시 저장 일지 요약) |

알림 종류별로 켜고 끌 수 있다. 일부 알림은 **이메일로도 받을 수 있다**(§6.7). 카카오 알림톡 등 그 밖의 외부 알림은 후순위(§17).

| 프로젝트 요약 | §10.7 |
| 월 공수표 | 월·프로젝트·직원별 공수(MD)·MM. **급여·정산 담당에 전달하는 용도** |

## 16. 개발 로드맵 (기능 기준)

기능 단위로 순서를 정한 계획이며, 기술과 구현 방식은 기술 기획에서 정한다. 직원 가입·초대·승인·직급 권한이 없어져 **초기 개발 범위가 크게 줄었다.**

| 단계 | 목표 | 포함 기능 | 완료 기준 |
|---|---|---|---|
| **0. 기반** | 회사별로 안전하게 들어와 쓸 수 있다 | 운영자의 회사·관리자 계정 생성, **정기 백업**, 로그인(아이디 + 카카오), **이메일 인증·비밀번호 셀프 재설정**, **약관·개인정보 동의와 처리방침 초안**, 회사 설정, **회사 간 격리 점검** | 두 회사를 만들어 서로의 자료가 어떤 화면에서도 나오지 않는다 |
| **1. 직원·프로젝트·투입** | 프로젝트별로 누가 몇 공수 일했는지 보인다 | 직원 카드·직종, 프로젝트 기본정보·상태, 투입 등록, 작업일지(일괄 입력), 공수 방식 설정, 직원별·작업 구분별 집계 | §9.5 예시 계산이 화면과 일치한다 |
| **2. 메모·사진·자재·자료** | 현장 기록이 한곳에 모인다 | 빠른 추가 버튼·메모함·프로젝트 메모 노트, 사진 업로드·사진첩, 자재 반입·사용·반출·잔량, 작업자료 문서함, 작업일보 출력 | 하루 일지 입력이 3분 안에 끝난다 |
| ★ **실사용 시험** | 1차 고객이 실제로 쓴다 | 1~2단계 범위로 1~2개 프로젝트를 실제 입력 | 관리자가 현장에서 쓰고 저녁에 정리한다. 불편 항목을 수집해 개선 |
| **3. 관리·경고** | 진행 상황을 놓치지 않는다 | 인력 배치 캘린더, 계획 공수·진행률·공수 소진율·경고, 변경·추가 작업 기록과 증빙, 프로젝트 상태 전환 규칙·요약, 대시보드·알림 | 예시(§10.4)대로 경고가 뜬다 |
| **4. 보증·확정** | 완료 후까지 이어서 관리한다 | 보증 기간, 보수 요청, 사후 작업 구분, 월 공수 확정·월 공수표, 직원 서류 만료 알림, 기록 조회 | 확정 후 숫자가 고정되고 재오픈 기록이 남는다 |
| **5. 안정화** | 지인 몇 팀이 계속 안심하고 쓴다 | 네이버·구글 로그인(필요 시), 계정 복구·해지 절차, 용량 관리, 처리방침·약관 최종 정비, 해지·데이터 내보내기 (운영자 콘솔·외부 알림·온보딩은 필요가 확인되면 §17) | 운영자가 직접 도와야 하는 일이 거의 없다 |

- 회사 격리는 0단계에서 한 번이 아니라 **모든 단계에서 새 기능이 추가될 때마다 다시 점검**한다.
- 상태 전환 규칙은 1단계에서 기본(예정~완료)을, 4단계에서 보증 중·종료 조건을 완성한다.

## 17. 확장 백로그

핵심 기능이 현장에서 안정적으로 쓰이고 실사용 요구가 확인된 뒤 추가한다.

**사용자·권한**
- **직원 계정·직원용 화면**(직원이 직접 사진·일지를 올림), 직원 초대·승인 흐름
- 직급별·프로젝트별 세분 권한, 작업일지 컨펌(승인·반려) 흐름
- 다회사 소속 계정(한 사람이 여러 팀을 운영하는 경우)
- **추가 사용자**(사무 담당·현장소장 계정), 직원 계정과 함께 쓰는 권한 설계
- 팀 간 협업(원청·협력 팀과 일부 프로젝트 정보 공유)

**현장 기능**
- 메모 문장으로 입력하면 일지·자재 항목으로 나눠 채워 주는 입력 보조
- 완전 오프라인 동작(도면 열람·일지 입력)
- 공정표(간트 차트), 작업 구분별 일정 관리
- 안전 점검·작업 전 안전 회의(TBM) 기록, 점검·검수 체크리스트
- 보수 요청 전용 접수·처리 관리(고객 접수 링크)
- 도면 위에 사진·메모 위치 표시
- 프로젝트 간 자재 이관 자동화, 공장·창고 재고 관리
- 근태(출퇴근·위치 확인) 기록

**서비스**
- 카카오 알림톡 등 이메일 외 외부 알림
- 회사 온보딩 마법사, 샘플 회사
- 고객 제출용 양식 템플릿

**돈 관련 (현재 범위 밖, 필요가 확인되면 별도 검토)**
- 프로젝트 계약 금액·청구·입금 기록
- 프로젝트 비용과 원가·이익 분석
- 회사 운영비·재무 현황

> 직원 급여·세금·4대보험은 확장 대상이 아니라 **이 서비스의 범위 밖**이다. 금액 관리를 포함한 이전 설계(v1.1)는 별도 파일로 보관되어 있다.

| 5 | **이메일도 못 쓰게 된 경우의 계정 복구** | 운영자가 사업자 정보·연락처 등으로 본인 확인 후 재설정 링크 발급. 확인 방법 결정 필요 |
| 6 | 프로젝트 상태 단계 | §10.3 제안(예정·진행·중단·완료·보증 중·종료·취소) 유지 여부 |
| 7 | 보증 기본값 | 보증 기간 12개월, 시작 기준은 실제 완료일 |
| 8 | 공수 소진율 경고 기준 | 80% / 100% |
| 9 | 작업 구분·공종·직종·자재 분류 프리셋 | §9.2, §10.2, §8.3, §11.2 제안 검토 |
| 10 | 프로젝트 코드 형식 | 연도-순번(예: 2026-012). 회사가 변경 가능 |
| 11 | 월 공수 확정 사용 여부 | 선택 기능(쓰는 회사만) |
| 12 | 사진 정책 | 자동 압축, 사진 위치 정보 처리, 회사별 용량 한도, 보관 기간 |

| 14 | 직원이 나중에 직접 입력하는 기능 | 초기 미지원. 필요가 확인되면 확장(§17) |
| 15 | 회사 단위 | 팀 하나가 하나의 회사(계정 1개)로 가입. 원청 아래 협력 팀을 묶는 구조는 미지원 |

| 19 | 직원 개인정보 동의 방식 | 회사가 직원에게 안내문(동의서) 양식을 받아 배포·보관. 서비스는 양식 제공까지만 |
| 20 | 이메일 알림 기본값 | 보안 알림(로그인·변경)은 항상 발송, 서비스 안내(보증 임박·미입력)는 선택 |
| 21 | 가입 대상 확인 | **확정**: 만 14세 이상. 가입 시 확인 문구 |

### 18.2 전문가(법무·세무사·노무사) 확인 필요

1. **개인정보 처리 구조**(§5.5): 관리자 정보는 운영자가 직접 처리, 직원 정보는 회사가 정하고 운영자는 수탁자라는 구분이 맞는지, 이용약관에 넣을 처리 위탁 조항 문구
2. **개인정보 처리방침**: 현행 작성지침에 맞는 필수 기재사항(공개 문의 창구 없이 운영자 직접 연락으로 갈음해도 되는지 포함), 수탁·위탁 현황, 국외 이전 기재 방식(사용할 외부 서비스가 정해진 뒤 확정)
3. **직원 동의**: 직원이 서비스에 접속하지 않고 회사가 입력하는 구조에서 동의·고지의 방식, 안내문 양식 검토
4. **법정 기한·기준**: 이용자 요청 처리 기한, 유출 시 통지·신고 기한과 대상, 접속 기록 보관 기간, 안전성 확보조치 중 소규모 사업자에 적용되는 범위
5. **사진·캡처 속 제3자 정보**와 위치 정보 처리
6. **공수 기록의 근로 관련 보존**: 투입 공수 기록이 근로 관련 자료로 간주될 수 있는 범위와 보존기간
7. **증빙 보존**: 계약서·대화 캡처의 보관 기간과 증거로서의 취급
8. **보증·하자 관련 계약 관행**: 보증 기간 기산일, 보증서 취급
9. 이메일 발송: 정보성 안내와 광고성 정보의 구분(마케팅 도입 시)

### 19.2 유지한 것
- 회사 간 완전 격리, 회사 코드는 내부용·로그인 때 입력하지 않음
- 로그인 수단(아이디 + 카카오·네이버·구글, 연동), 비밀번호 본인 변경
- 투입·작업일지 구조, 공수 입력 방식(비율/시간, 분 단위 저장), 월 공수 확정(선택)
- 프로젝트 기본정보·상태·보증 기간·변경 작업 기록, 사용 자재, 사진·작업자료

### 19.3 점검: 한 명이 전부 쓰는 구조에서 생기는 빈틈

| 항목 | 반영 |
|---|---|
| 계정을 잃으면 회사가 잠김 | 이메일 셀프 재설정(§6.7), 마지막 수단은 운영자 본인 확인 복구(§6.3, §18.1 #5) |
| 계정 하나가 모든 데이터를 열 수 있음 | 2단계 인증 권장, 내보내기 재인증, 기기 목록(§6.3, §7.3) |
| 직원이 확인하지 않은 기록이라 공수 분쟁 가능성 | 수정 이력·사진·메모 기록으로 보완(§9.4), 월 공수표를 출력해 팀원에게 전달 가능(§15.4) |
| 팀장이 바뀌거나 사무 담당이 대신 입력해야 함 | 계정 소유자 이전(§6.6), 추가 사용자는 확장(§17) |
| 현장에서 프로젝트를 고를 겨를이 없음 | 메모함(§14) |
| 직원 개인정보를 직원 동의 없이 입력 | 회사 책임 명시, 직원용 안내문 양식 제공(§5.8), 전문가 확인(§18.2) |
| 이메일 계정 탈취 시 서비스 계정 위험 | 2단계 인증 권장, 재설정·변경 알림, 내보내기 재인증(§6.7, §7.3) |
| 기기 분실 시 보안 | 로그인 기기 목록·원격 로그아웃(§6.4) |

### 19.4 남은 위험과 주의
- **입력 부담**: 관리자가 현장에서 기록하지 않으면 모든 기록이 비어 있다. 메모함, 3분 입력 목표, 모바일 사용성을 실사용 시험에서 반드시 검증한다.
- **진행률의 주관성**: 진행률은 담당자 입력값이라 경고의 정확도에 한계가 있다. 갱신 알림으로 보완한다.
- **직원 확인 부재**: 공수 기록을 직원이 확인하지 않는다. 정산 분쟁이 생기면 관리자 기록과 사진·메모가 근거가 된다.
- **사진 용량**: 현장 사진은 저장 용량이 빠르게 늘어난다. 압축·보관 기간·용량 한도 정책을 일찍 정한다.
- **백업·데이터 손실**: 계정과 데이터가 하나뿐이라 서버 장애·삭제 실수가 곧 기록 전체 손실이다. 정기 백업과 복구 확인, 관리자의 전체 데이터 내보내기를 0~2단계에서 일찍 준비한다(§20 보안 운영).
- **지인 한정이라도 개인정보 의무는 남는다**: 직원 이름·연락처·서류가 저장되므로 동의·처리방침·유출 대응의 최소 형태는 유지한다(§5).
- **범위 관리**: 1인 개발이므로 §16의 단계를 넘는 기능은 실사용 검증 뒤에 추가한다.
