## 3. 디자인 원칙 (AI 템플릿처럼 보이지 않게)

- **카드는 덜 쓴다**: 화면의 주 구역은 흰 바탕 위 제목 + 얇은 구분선으로 나눈다. 카드는 "따로 떼어 볼 묶음"(수치 요약, 목록 행 묶음)에만 쓰고, 카드 안에 카드를 넣지 않는다
- **색은 의미에만**: 파란색은 주 동작 1개와 선택 상태에만. 경고는 행 앞의 작은 점·아이콘 + 글자로, 빨간 상자는 저장 실패 같은 오류에만
- **모서리 단계**: 입력·버튼 8px, 패널 12px, 알약 모양은 배지·칩에만 (지금은 버튼·패널·입력 모두 크게 둥글다)
- **글자 위계**: 화면 제목 22/600, 구역 제목 16/600, 본문 15/400, 보조 13/400, 숫자는 고정폭 숫자(`tabular-nums`)로 정렬. 글자 크기 단계는 5개만 쓴다
- **간격**: 4px 단위 (4·8·12·16·24·32·48). 구역 사이 32, 구역 안 16
- **그림자**: 떠 있는 것(팝오버·메뉴·모달·저장 줄)에만. 놓여 있는 패널은 테두리만
- **표 중심**: 기록이 쌓이는 화면(작업 기록·비용·단가표·자재)은 카드 나열 대신 표. 모바일은 표를 "두 줄 행"으로 바꿔 보여 준다 (가로 스크롤 금지)
- **화면마다 첫 동작 하나**: 머리 오른쪽에 주 버튼 1개. 같은 동작을 여러 곳에 두지 않는다. 오른쪽 아래 + 버튼은 모바일에서만, 그 화면의 주 동작과 같을 때만
- **폼은 접어 둔다**: 등록·변경 폼은 버튼을 눌러 모달(넓은 화면) 또는 아래에서 올라오는 시트(모바일)로 연다
- 이모지·그라데이션·장식용 일러스트·의미 없는 아이콘 나열은 쓰지 않는다

## 4. 컴포넌트 체계 (R-1)

### 4.1 크기 단계

모든 입력형 요소와 버튼이 같은 `size`를 받는다. 같은 줄에 놓으면 높이가 맞는다

| size | 높이 (모바일 / 넓은 화면) | 글자 | 쓰는 곳                               |
| ---- | ------------------------- | ---- | ------------------------------------- |
| `sm` | 36 / 32                   | 14   | 표 안, 필터 줄, 툴바                  |
| `md` | 44 / 40 (기본)            | 15   | 일반 폼                               |
| `lg` | 52 / 48                   | 16   | 현장 입력(하루 작업의 시간·사람 추가) |

### 4.2 대상 컴포넌트

| 컴포넌트            | 바뀌는 점                                                                                                                                          |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Select`            | 기기 기본 선택 칸 → Radix Select 기반 목록(이미 쓰는 `radix-ui`, 새 의존성 없음). 콤보박스와 같은 열린 모양·체크 표시·키보드. 크기 단계, 비움 선택 |
| `Combobox`          | 크기 단계, 묶음(예: "프로젝트 팀" / "다른 직원"), 보조 설명, 여러 개 고르기(`multiple`), 목록에 없을 때 "새로 추가" 동작                           |
| `Input`·`DateInput` | 크기 단계, 앞뒤 붙임(아이콘·단위 "원"·"시간")                                                                                                      |
| `MoneyInput` (새)   | 천 단위 쉼표 표시, 숫자만 입력, 값은 정수(원)                                                                                                      |
| `Button`            | 크기 단계 정리, 아이콘 버튼 크기 통일, 모서리 8px                                                                                                  |
| `Field` (FormField) | 라벨·도움말·오류 위치 통일, 가로 배치(라벨 왼쪽) 옵션                                                                                              |
| `Section` (새)      | 카드 없이 제목·설명·오른쪽 동작·구분선만 있는 구역                                                                                                 |
| `StatGroup` (새)    | 큰 숫자 + 라벨 여러 개를 한 줄로 (카드 하나에 칸만 나눔)                                                                                           |
| `Sheet` (새)        | 모바일 아래에서 올라오는 시트, 넓은 화면에서는 모달. Radix Dialog 기반                                                                             |
| `DataTable`         | 크기 `sm` 행, 모바일 두 줄 행 표시, 행 끝 더보기 메뉴                                                                                              |
| `StatusDot` (새)    | 경고·상태를 작은 점 + 글자로 (빨간 상자 대체)                                                                                                      |

- Storybook `Foundations/컴포넌트 모음`에 크기 × 상태(기본·포커스·오류·비활성) 표를 만든다
- 기존 사용처는 모두 새 컴포넌트로 바꾸고, 기기 기본 `<select>`는 남기지 않는다

### 4.3 서드파티

새로 들이는 라이브러리는 없다. 이미 있는 `radix-ui`(Select·Dialog·Popover), `cmdk`, `@tanstack/react-table`, `react-day-picker`로 충분하다. 금액 입력은 직접 만든다(작은 로직, 의존성 추가보다 낫다)

## 5. 프로젝트 작업 공간 (R-2~R-4)

### 5.1 현장의 일 흐름

1. 프로젝트를 만들고 **기간**(시작·종료 예정일)과 **팀**(투입할 직원)을 정한다
2. 달력에 **날마다 누가 나갈지 계획**을 잡아 둔다 (여러 날·여러 명 한 번에)
3. 당일에는 계획을 불러와 **실제로 누가 몇 시간 일했는지** 확정한다 (사람마다 시간이 다를 수 있다)
4. 그날 찍은 **사진**, 들어온·쓴 **부자재**, 나간 **비용**·들어온 **수입**을 같이 남긴다
5. 진행 중에 **추가 공사**를 협의하고, 끝나면 **마감·보증**으로 넘긴다

### 5.2 메뉴 11개 → 5개

| 새 메뉴              | 담는 것                                                                                   | 지금 메뉴                   |
| -------------------- | ----------------------------------------------------------------------------------------- | --------------------------- |
| **개요**             | 기간 진행 막대, 진행 단계, 이번 주 투입, 비용·수입 합계, 확인할 일(경고)                  | 현황                        |
| **작업 기록** (기본) | 월 달력(날짜마다 인원·시간) + 날짜를 누르면 그날 기록: 사람·시간, 한 일, 사진, 자재, 비용 | 작업 달력                   |
| **인원**             | 프로젝트 팀, 사람별 일한 날·시간·인건비 추정, 필요 자격                                   | 인원, 공수·인건비           |
| **비용·자재**        | 비용·수입 내역(새), 자재 잔량·기록, 추가 공사                                             | 자재, 추가 공사 (+ 새 기능) |
| **자료**             | 사진·문서·메모를 한 화면에서 종류 칩으로 거른다                                           | 사진, 문서, 메모            |

- **마감·보증**: 상태가 완료 이후일 때만 메뉴에 나타난다 (그 전엔 개요의 진행 단계에서 안내)
- **정보 수정·일보 출력·프로젝트 안에서 찾기**: 머리 오른쪽 더보기(⋯) 메뉴로
- 옛 주소(`/projects/:id/photos` 등)는 새 위치로 자동 이동

### 5.3 프로젝트 머리

- 한 줄: 번호·이름·상태 배지·남은 기간. 둘째 줄: 현장·고객·담당자·기간 (작게)
- 주 버튼 1개: 진행 중이면 `오늘 기록`, 예정이면 `작업 시작`, 완료면 `보증 시작`, 종료·취소면 없음
- 본문의 중복 버튼과 오른쪽 아래 + 버튼은 프로젝트 안에서 쓰지 않는다

### 5.4 작업 기록 (첫 화면)

- 달력은 **오늘이 든 달**(기간 밖이면 기록이 있는 가장 최근 달)로 열고, 프로젝트 기간 밖은 흐리게
- 날짜 칸: 기록한 날은 인원 수·총 시간(진한 표시), 계획만 있는 날은 계획 인원(테두리 표시), 사진·비용이 있으면 작은 표시. 계획과 실제가 다르면 차이 표시
- 넓은 화면은 달력 왼쪽 + 고른 날의 요약 오른쪽(2열), 모바일은 달력 아래에 목록
- 날짜를 누르면 하루 기록으로 이동. 오늘 이후 날짜는 계획 편집으로

### 5.4.1 투입 계획

- `계획 잡기`: 날짜 여러 개(달력에서 드래그·여러 번 누르기, 또는 기간 + 요일 선택)와 팀원 여러 명을 골라 한 번에 넣는다
- 같은 직원이 같은 날 다른 프로젝트에 계획돼 있으면 경고 (막지는 않음)
- 하루 기록을 처음 열면 그날 계획 인원이 미리 채워진다 (기본 시간은 하루 8시간, 저장 전까지 고칠 수 있음). 계획이 없으면 빈 상태로 시작
- 인력 배치 화면(회사 전체 달력)에 계획이 같이 보인다 (R-6)
- 데이터: 새 테이블 `project_day_plans` (프로젝트·날짜·직원, 메모 선택). 계획은 기록이 아니라서 수정·삭제 자유, 회사 범위 테이블 규칙(RLS·`PURGE_POLICY`·격리 테스트) 적용

### 5.5 하루 기록 (`/projects/:id/work/:date`)

위에서 아래로 순서대로 채운다 (2026-10-14 사용자 결정):

1. **일한 사람**: 회사 직원 표(이 현장 투입 인원이 먼저, "이 현장" 표시)에서 체크로 고른다. 체크를 풀면 그날 기록에서 빠진다. "프로젝트 팀 N명 모두 넣기"는 두지 않는다
2. **일한 시간**: 고른 사람마다 −/+ 30분·반일·하루·연장. 처음에는 하루(8시간). 여러 명이면 머리에 "모두 반일/하루/연장"
3. **한 일**: 사람마다 작업 구분. 한 사람이 여러 일을 했으면 "다른 일도 했어요"로 나누고 일마다 시간. 여러 명이면 "모두 같은 일로"
4. **그날 작업**: 작업 내용·구역·날씨·특이사항·변경 작업 표시
5. 그 아래 사진·자재, 아래 고정 줄 `3명 · 24시간` + 임시 저장·저장

- "같은 내용을 다른 날짜에도 저장"은 없앤다. 대신 머리에 **다른 날짜에서 불러오기**(기본은 가장 최근 기록한 날)
- 빠른 추가(+) 버튼은 모바일의 프로젝트 밖 화면에서만 (저장 줄과 겹치지 않게)

### 5.6 인원 (투입 인원 통계)

- 작업 달력에 기록한 사람들의 **합계를 보는 곳**이다 (2026-10-14 사용자 결정). 사람을 넣고 빼는 것은 작업 달력의 날짜에서만 한다
- 수치 줄(일한 사람·작업한 날·총 일한 시간·하루 평균 인원) + 사람별 표(일한 날·총 시간·하루 평균·일한 기간·한 일별 시간). 기간: 전체·이번 달·지난 달
- 투입 등록(기간·계획 공수) 관리 화면은 두지 않는다. 투입은 하루 기록을 저장할 때 자동으로 생긴다(기존 규칙). 필요 자격은 정보 수정으로 옮긴다
- 공유 집계(`summarizeProjectWork`)의 사람별 항목에 처음·마지막으로 일한 날과 작업 구분별 시간을 더했다

### 5.7 현황

- 보기와 상태 처리만 한다 (2026-10-14 사용자 결정): 진행 현황(진행률·공수 소진율·투입 공수·끝내려면 필요한 공수, 경고) + 진행 단계(완료·중단·취소) + 프로젝트 정보
- "지금 남기기"(오늘 작업·사진·자재·메모 바로 가기)와 겹치던 수치 카드는 없앤다
- 진행률은 `진행률 바꾸기` 창에서 10% 단위 단추 한 번 또는 직접 입력. 기준일은 오늘, 메모는 받지 않는다. 이력은 접어 둔다

## 6. 비용·수입 기록 (범위 변경, R-4)

> 서비스 기획서 v2.4는 "비용·수입 등 돈 관리는 범위 밖"으로 정했다. 요청 5에 따라 **프로젝트에서 나간 돈(부자재·장비·식대 등)과 가끔 생기는 수입(고철 판매, 현장에서 일을 도와주고 받은 돈 등)의 기록**만 범위에 넣는다. 계약 금액·청구·입금 관리, 회계·세금·급여는 계속 범위 밖이다. 서비스 기획서 머리말·범위표에 반영하고 결정 007로 남긴다

### 6.1 데이터 (새 테이블 `project_ledger_entries`)

| 항목           | 내용                                                                                               |
| -------------- | -------------------------------------------------------------------------------------------------- |
| 날짜           | 지출·입금 날짜                                                                                     |
| 구분           | 지출 / 수입                                                                                        |
| 분류           | 지출: 부자재·장비·운반·식대·기타, 수입: 고철 판매·현장 지원·기타 (목록 관리로 회사가 바꿀 수 있음) |
| 금액           | 원 단위 정수 (0 초과)                                                                              |
| 거래처         | 명부에서 선택 (선택)                                                                               |
| 내용·메모      | 짧은 글                                                                                            |
| 증빙           | 사진·PDF 첨부 (선택, 기존 파일 저장소 사용)                                                        |
| 추가 공사 연결 | 추가 공사 번호 (선택)                                                                              |

- 회사 범위 테이블: RLS·`PURGE_POLICY`·격리 테스트 목록에 넣는다. 지우면 소프트 삭제, 변경은 감사 기록
- 계산 규칙(지출 합계·분류별 합계·수입 합계)은 shared 순수 함수

### 6.2 화면

- 비용·자재 메뉴의 첫 구역: 합계 줄(지출 · 인건비 추정 · 수입) + 내역 표(날짜·구분·분류·내용·거래처·금액) + 구분·분류·기간 필터. 지출이 기본이고 수입은 구분 단추로 바꿔 입력
- 하루 기록에서도 그날 비용을 한 줄 추가할 수 있다
- 개요에 합계만 보인다

### 6.3 자재 입력 다시 설계 (R-4)

> 판금 인테리어는 현장마다 들어가는 자재가 다르다: 철문, 샷시 판금, 후레싱, 커버처럼 **그 현장 치수·두께·색에 맞춰 만든 것**이 대부분이다. 회사 자재 목록에서 골라 넣는 지금 방식은 이런 맞춤 자재를 담지 못한다

#### 6.3.1 지금의 문제

- 입력이 "자재 골라서 추가"부터 시작한다. 목록에 없으면 `새 자재`로 회사 자재를 먼저 등록해야 해서 한 줄 쓰는 데 두 단계가 걸린다
- 맞춤 자재는 현장마다 이름·치수가 달라 목록에서 고를 일이 거의 없다
- 품명과 수량뿐이라 **치수·두께·재질·색·설치 위치**를 적을 곳이 마땅치 않다

#### 6.3.2 바꾸는 방식: 쓴 자재를 그 자리에서 적는다

- **잔량·반입·반출·폐기는 다루지 않는다**. 이 현장에 **어떤 자재를 얼마나 썼는지**만 기록한다 (2026-10-14 사용자 결정)
- 자재 한 줄 = **품명 · 규격(치수·두께·재질·색을 자유롭게) · 수량 · 단위 · 위치 · 메모**. 고르는 게 아니라 쓴다
  - 예: `철문` · `900×2100 1.6T 백색` · 2 · 개 · 3층 301호
- 품명 칸은 회사가 전에 쓴 품명을 추천만 하고, 새 품명·규격은 저장할 때 회사 자재로 자동 등록된다. 같은 품명·규격이면 같은 자재 (`findMaterialMatch`)
- 단위는 전에 쓴 자재면 미리 채우고, 자재마다 단위는 하나
- `줄 복사`로 치수만 다른 맞춤 자재를 여러 개, `최근 쓴 자재` 칩으로 한 번에 줄 추가
- 화면: 기록 입력 → 자재별 합계(쓴 양) → 날짜별 기록(지우기). 예전에 남긴 반입·반출·폐기 기록은 구분 표시만 붙여 보여 준다
- 금액은 지출 기록(§6)에서 따로 다룬다

#### 6.3.3 데이터

- 회사 자재 목록(`materials`)은 **사용자가 따로 관리하는 목록이 아니라 자동으로 쌓이는 추천 목록**이 된다: 새 품명·규격으로 저장하면 서버가 자동으로 만든다 (지금도 같은 이름·규격은 하나로 묶는 규칙이 있음)
- 기록은 기존 자재 기록(구분은 사용)을 쓰고, 위치는 `area`, 규격은 자재의 `spec`을 쓴다. 스키마 변경 없음
- 목록 관리 화면의 "자재"는 오래 안 쓴 항목 숨기기·이름 합치기 정도만 남긴다

## 7. 직원·단가 (R-5)

- **직원 목록**: 표에 `현재 단가`(종류·금액) 열 추가, 단가 없는 직원 표시. 상단 필터는 한 줄 도구 줄로 줄이고 `간편 등록`은 머리 버튼 → 시트
- **단가표 탭** (직원 화면 안 `직원 목록 | 단가표`): 직원별 현재 단가·적용 시작일·이전 단가·변경일을 한 표로. 여기서 바로 `단가 변경`
- **직원 카드**: 머리에 상태·직종·현재 단가·이번 달 공수를 수치 줄로. 탭 `개요 · 투입 이력 · 단가 · 서류·자격 · 기본정보`
  - 단가 탭: 현재 단가 크게 + 일 환산(시급제·월급제일 때) + 변경 이력 타임라인(언제부터 얼마, 누가 바꿈). `단가 변경`은 시트로
  - 서류·자격: 목록 표 + `서류 등록` 시트 (지금의 늘 펼친 폼 제거)
- 단가 조회 감사 기록(`PAY_RATE_VIEWED`)은 단가표를 열 때 한 번 남긴다

## 9. 결정 (2026-10-14 사용자)

1. 비용·수입: 지출 중심 + 가끔 생기는 수입(고철·현장 지원). 계약 금액은 두지 않는다
2. 투입 계획: 둔다 (§5.4.1)
3. 커밋은 단계마다 확인 뒤, PR은 모든 단계가 끝난 뒤 한 번
4. 인원: "팀에서 빼기"는 쓰지 않는다. 투입 인원·투입 취소·투입 종료로 (§5.6)
5. 자재: 목록에서 고르지 않고 현장 맞춤 자재를 그 자리에서 쓴다. 제작 진행 단계·잔량은 두지 않는다 (§6.3)
6. 하루 기록: 직원 표에서 고르기 → 시간 → 한 일 → 그날 작업 순. 다른 날짜에 저장 대신 다른 날짜에서 불러오기 (§5.5)
7. 인원: 작업 달력 기록의 통계만 (§5.6). 현황: 보기와 상태 처리, 진행률은 간단히 (§5.7)
