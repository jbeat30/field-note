# 1단계. 개발 순서 세부 설계

> 기준: `00-analysis.md`, 서비스 기획서 §16, 기술 기획서 §16
> 원칙: 한 번에 한 덩어리(PR 크기)로 끝내고, 각 덩어리마다 **완료 기준을 테스트로 고정**한다. 새 기능이 추가될 때마다 회사 격리 테스트를 함께 늘린다.

## 0. 진행 규칙

- 작업 단위 ID: `T0-1`(기술 0), `P0-1`(0단계), `P1-1`(1단계) …
- 커밋 메시지: `타입: 한국어 설명` 형식 (`feat` `fix` `docs` `chore` `refactor` `test` `style`)
- 모든 의존성은 정확한 버전으로 고정, 정식 릴리스만 사용
- 코드·주석은 jbeat-conventions를 따른다 (한국어 명사형, 마침표 없음)
- 각 단계 종료 시 `pnpm typecheck && pnpm lint && pnpm test`가 통과해야 한다

## 1. 전체 흐름

```
T0 기술 준비 ─▶ P0 기반 ─▶ P1 직원·프로젝트·투입 ─▶ P2 메모·사진·자재·자료
                                                          │
                                                          ▼
                              P5 안정화 ◀ P4 보증·확정 ◀ P3 관리·경고 ◀ ★ 실사용 시험
```

의존 원칙: **격리(T0-4) → 인증(P0) → 업무 데이터(P1) → 파일(P2)** 순서는 바꿀 수 없다.
화면은 각 단계에서 API가 먼저 완성된 뒤 붙인다.

## 8. 결정 기록 (ADR 후보)

| 번호 | 결정 | 이유 |
